# 使用手册 · 静默一键启动与桌面应用

> 面向「把云枢智能统一平台跑起来给人看」这件事。只讲怎么用、出问题怎么查。
> 机制与实测取证见 `_evidence/shell/D20-silent-launch-desktop-app.md`。

## 一、30 秒上手

双击桌面的 **云枢智能 一键启动**（蓝底 logo 图标）。

什么都不会弹出来 —— 约 2 秒后浏览器自动打开 <http://127.0.0.1:8800>，约 8–12 秒后 15 个服务全部就绪。
首屏就是作品集，不登录也能整屏读完；点「进入演示」再登录。

P01 客服要连的 **MySQL 是 Docker 容器**（`customer-service-mysql`，宿主 3307），不在那 15 个进程里。
一键启动会顺手把它带起来：3307 没监听 → 需要时拉起 Docker Desktop（本机实测引擎 15.9s 就绪）→ `compose up -d`。
不想让它碰 Docker 就 `pythonw _tools\launcher.py start --no-mysql`（代价：客服页会报两个加载失败，见第六节）。

没有桌面图标了（换机器 / 仓库搬家 / 删了）？在仓库根目录跑一次：

```bat
python -X utf8 _tools\make_desktop_app.py
```

它会重建图标、`_tools\dist\云枢智能.exe` 和桌面三个快捷方式。

## 二、桌面三个图标

| 图标 | 双击之后 | 实测 |
|---|---|---|
| **云枢智能 一键启动** | 先确保 P01 的 MySQL 容器在 3307（需要时拉起 Docker Desktop），再静默起 15 个服务（已在跑的自动跳过），门户端口一通就开浏览器；全好了就安静退出 | 门户 +2s，15/15 在线 +8~12s（依赖已装的暖启动）；MySQL 容器现起 1.8s |
| **云枢智能 停止服务** | 静默停全部服务，连占用端口的旧进程一起收（`--takeover`） | 8s 内全部端口释放 |
| **云枢智能 服务状态** | 弹窗列出 15 个进程逐个 TCP 实测结果（绿不绿不由界面猜，是探测） | 一屏看完 |

三条要记住的行为：

- **只在服务没起来时才会弹一个框**，内容是「门户已可访问，但这些端口没起来：xxx」，选「是」直接打开日志目录。全好了不会打扰你。
- **连点两次没副作用**：入口有命名互斥量，第二次会直接跳过，不会重复起服务抢端口。
- 图标是快捷方式，指向仓库里的 `_tools\dist\云枢智能.exe`。可以右键「固定到开始屏幕 / 任务栏」。

## 四、端口与模块对照

端口唯一真源是 `shared/config/services.json`（SERVICE_REGISTRY），改端口只改它，然后跑
`python shared/config/build_js.py` 重新生成前端镜像。**不要在模块代码里硬编码别的模块端口。**

| 层 | 模块 | 进程 id | 端口（Web / API） | 挂载路由 |
|---|---|---|---|---|
| — | 统一外壳网关 | `shell` | **8800** | 入口 `http://127.0.0.1:8800` |
| L3 | P01 AI 电商客服 | `p01-web` / `p01-api` / `p01-commerce` | 5173 / 18082 / 18081 | `/workspace/customer-service` |
| L3 | P02 电商运营助手 ★ | `p02-web` / `p02-api` | 3001 / 8000 | `/workspace/ecommerce-ops` |
| L2 | P03 NL2SQL 问数 | `p03-web` / `p03-api` | 5174 / 8030 | `/workspace/research` |
| L2 | P04 RAG 知识库 | `p04` | 8041 | `/workspace/knowledge` |
| L3 | P05 合同审批 | `p05` | 8770 | `/workspace/contract` |
| L0 | P06 数据中台 | `p06` | 8060 | `/workspace/data-platform` |
| L2 | P07 AI 素材中心 | `p07` | 8070 | `/workspace/asset-center` |
| L2 | P08 直播切片 | `p08` | 8080 | `/workspace/live-clip` |
| L3 | P09 AI 销售考核 | `p09` | 8090 | `/workspace/sales-assessment` |
| L1 | P10 模型微调平台 | `p10` | 8101 | `/workspace/finetune` |

侧栏那个绿/灰点是真探活：`GET /api/services/health` 由各模块端口 TCP 监听状态决定，灰 = 没启动。
没启动的模块在挂载区会直接给出可执行的启动命令，而不是一个空白 iframe。

## 五、不想用图标时（等价命令行）

```bat
start-all.bat                                  :: 起全部，带一个进度窗口（会 pause，方便看输出）
stop-all.bat                                   :: 停全部（含接管旧进程）
pythonw _tools\launcher.py                     :: 和「一键启动」图标完全等价，零窗口
pythonw _tools\launcher.py stop                :: 等价「停止服务」
python  _tools\launcher.py status              :: 等价「服务状态」（不落弹窗，直接打印）
python  _tools\launcher.py open                :: 只打开门户，不动任何进程

python -X utf8 _tools\supervisor.py status --verbose   :: 没起来的，顺带打它自己的日志尾部
python -X utf8 _tools\supervisor.py restart p04        :: 只重启某个服务
python -X utf8 _tools\supervisor.py start p06 p07      :: 只起指定的几个
```

只想省内存不看全平台：`start p01 p02 p06` 这种按 id 起就行，端口仍从注册表解析。

## 六、出问题怎么查

日志一律在 `_runtime\logs\`：每个服务一份 `<进程id>.log`，启动器自己一份 `launcher.log`。
PID 记录在 `_runtime\pids\`。

| 现象 | 先查 | 处置 |
|---|---|---|
| 双击图标啥也没发生 | `_runtime\logs\launcher.log` 末尾 | 多为 pythonw 路径变了（换过 Python 版本）→ 重跑 `python -X utf8 _tools\make_desktop_app.py` |
| **客服页报「加载历史消息失败 / 加载订单列表失败」** | `_runtime\logs\p01-api.log` 里若是 `Can't connect to MySQL server on '127.0.0.1'` | P01 的 MySQL 容器没起（3307 无人监听）。重跑一次一键启动（它现在会带起 Docker），或手动：`docker compose -f projects\p01-ai-customer-service\external\docker\docker-compose.yml up -d` |
| 弹「外壳网关没起来」 | `_runtime\logs\shell.log` | 8800 被别的进程占了：`python -X utf8 _tools\supervisor.py stop --takeover` 再点图标 |
| 弹「有依赖没就绪」 | 点「是」打开日志目录 | 文案会点名是哪些端口、还是 P01 的 MySQL 没起；单个服务修好后 `supervisor.py restart <id>`，不用整体重启 |
| **代码改了但页面还是老样子** | `supervisor.py status` 看端口 | 九成是端口上跑着**旧进程**：`stop --takeover` 或 `restart <id>` 接管过来 |
| 又冒出一堆黑色窗口 | 起服务的那条路径的标志位 | 必须是 `CREATE_NO_WINDOW`；`DETACHED_PROCESS` 在 Win11「默认终端 = Windows Terminal」下照样给每个服务开窗口（这就是本次返工的根因） |
| 服务莫名全没了 | 是不是 `taskkill /PID <launcher> /T` 杀的 | 服务是启动器的子孙进程，`/T` 会一起带走。停服务请用「停止服务」图标或 `stop-all.bat` |
| 想确认是不是真在线 | 「服务状态」图标 | 逐个 TCP 探测，不看界面脸色 |

模型调用不通不算启动故障：所有模型调用走 `shared/llm-gateway`，根目录 `.env` 凭证不齐时会**退回 mock 并在 UI/README 标注**，服务照样能起。

| 想改 | 改哪 | 生效方式 |

## 八、可选：开机自启 / 快捷键

- **开机自启**：`Win+R` → 输入 `shell:startup` → 把「云枢智能 一键启动」的快捷方式拖进去。（本手册只写做法，**没有替你这台机器配置**。）
- **键盘唤起**：右键快捷方式 → 属性 → 「快捷键」设为 `Ctrl+Alt+Y` 之类。
- **给手机 / 同桌同事看**：用本机局域网地址 `http://<WLAN 的 IPv4>:8800`。IP 是 DHCP 分的，会变，
  别照抄文档里的旧数字 —— 现场读一遍：`ipconfig` 只看**「无线局域网适配器 WLAN」**那一行的 IPv4
  （本轮实测 `192.168.1.109`；`198.18.0.1` 是「快车VPN」的 fake-IP、`192.168.10.1` 是 VMware 虚拟网卡，
  这两个手机都连不到）。手机要和电脑**同一个 WiFi**，且路由器没开 AP 隔离。
  **公网入口至今没打通**，原因和三条出路见 `_evidence/shell/D13-portfolio-home.md` 第三节 ——
  面试官远程访问这条仍然是未完成，别当成已交付。

## 九、边界（别当成已完成）

- 手册里的 2s / 8~12s 是**依赖已装的暖启动**实测；首次冷启动还要加 `uv sync`、`npm install` 的时间，本轮未测。
- `start-all.bat` 仍会开**它自己那一个**控制台窗口（它就是给人看进度并 `pause` 的），要零窗口请用桌面图标或 `pythonw _tools\launcher.py`。
- P01 自带的 `projects/p01-ai-customer-service/tools/dev_up.py` 仍用 `CREATE_NEW_CONSOLE` —— 那是它文档里写明的模块级设计（「窗口即日志」），统一平台路径不经过它，本手册不管它。
- **只并入了 P01 的 MySQL 这一个 Docker 依赖**。同一台 Docker 上 `milvus-standalone / milvus-minio / milvus-etcd`（P04 向量库）本轮实测仍是 `Exited`，P03 的 MySQL(3306)/RAGFlow(9380) 也仍未启动 —— **P04 端口 8041 在听不等于检索可用**；要用这两条得自己 `docker compose -f <对应 compose> up -d`（或让我把它们也并进启动器，属需确认的改动）。
- 桌面 exe 是本地编译的启动器，不是安装包；换机器需要在新机器重跑一次 `make_desktop_app.py`。
