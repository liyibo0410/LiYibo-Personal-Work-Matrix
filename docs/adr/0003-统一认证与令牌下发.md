# 0003 · 统一认证：外壳网关签发，postMessage 下发，模块只校验

- 状态：Accepted（P02 例外见「后果」）
- 日期：2026-10-13

## 背景

规范要求「统一认证：共用 JWT/Session，`shared/auth` 提供签发与校验，各模块只校验不自己实现登录」。但十个模块成熟度不一：P02 已有完整的邮箱登录 + httpOnly Cookie + 四角色 RBAC；其余多数模块此前无登录或仅有占位。

## 决策

- 外壳网关 `shell/serve.py` 用 `shared/auth`（`issue_token/verify_token`，HS256）提供 `/api/auth/login`、`/api/auth/verify`。演示账号 owner/ops/legal/sales/admin，密码本地演示、已文档化；生产须设 `CP_AUTH_SECRET` 并接真实用户体系。
- 登录一次拿到令牌，挂载模块时通过 postMessage `cp:auth` 下发；模块侧 `ui-kit.js` / 构建型垫片接收后持有令牌用于调用自身后端。
- 模块**只校验不重造登录**这一原则对无自有登录的模块成立。

## 后果

- (+) 单一登录入口、单一令牌签发与校验实现（`shared/auth`），符合「四统一」的认证项。
- (−) **P02 保留自身 Cookie 会话**：它已有完整 RBAC 与 httpOnly 令牌，强行改成消费外壳 `cp:auth` 会绕过其权限模型、风险大于收益。因此 P02 的桥接垫片**只同步主题、不接管令牌**（避免半成品鉴权逻辑）。这是「统一认证」的一处**有意识的例外**，在 0005 与 P02 README 中标注。
- (−) 演示账号密码写在 `serve.py`：仅限本地联调，红线要求生产替换。
