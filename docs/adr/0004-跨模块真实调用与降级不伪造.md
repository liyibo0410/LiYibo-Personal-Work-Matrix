# 0004 · 跨模块取数走真实 HTTP，降级路径不伪造数据

- 状态：Accepted
- 日期：2026-10-13

## 背景

数据流闭环要求 P02 消费 P06 指标、P09 消费 P01 会话。红线要求「跨模块取数必须真实 HTTP 调用并留日志」，同时「禁止把 mock 冒充真实」「没有测量就写未测量」。两条要求看似冲突：既要真调用，又要能在依赖不可用时优雅降级。

## 决策

每条跨模块链路实现**正常 + 降级**双路径，用响应里的 `source` 字段自证：

- 地址一律 `cloudpivot_config.api_url("p06", ...)` / `api_url("p01", ...)` 从注册表解析，**不硬编码对方端口**；支持 `CP_*` 环境变量覆盖。
- **P02→P06**：`/api/v1/dashboard/overview` 正常返回 7 项指标 + `source=p06-live`；P06 不可达时返回 `ok=False / degraded=True / source=unavailable` 且**不含 metrics 字段**（不编数）。前端双处标注（绿色实时 / 黄色降级）。
- **P09→P01**：`POST /api/v1/import/from-p01` 真实拉取 P01 MySQL 会话，按 `session_id` 聚合、角色映射 user/bot→customer/agent 后规则评分（`source=p01-live`）；不可达时 `imported=0`，不伪造。
- 健康探针用 `service_url`（P01 探针在根 `/health`，不在 `/api` 前缀下）。

## 后果

- (+) 「真调用」与「不伪造」同时满足：降级态是**显式、可区分、不含假数据**的。
- (+) 调用日志与证据落 `_evidence/pXX/cross-module-*.md`。
- (−) 降级判断依赖超时/异常，需要为「依赖在线/离线」各留一条真实用例（已各留正常 + 降级演练）。
