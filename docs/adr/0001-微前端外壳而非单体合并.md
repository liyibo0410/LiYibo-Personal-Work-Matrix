# 0001 · 集成形态：微前端外壳 + iframe/postMessage，而非单体合并

- 状态：Accepted
- 日期：2026-10-13

## 背景

十个 AI 能力模块技术栈异构：P02 是 Next.js 16 + React 19 + Tailwind v4；P01/P03 是 Vue 3 + Vite；P04~P10 是 FastAPI 直接托管静态页。要求「合并为一套统一系统」，但把它们重写进同一个前端工程（单体）意味着：统一框架、统一构建、迁移全部业务代码，成本高、风险大，且抹掉各模块原本的技术选型叙事（面试要讲的就是「异构系统如何整合」）。

## 决策

采用**微前端外壳**：`shell/` 提供登录、分层导航、主题切换与「智能体矩阵」首页；各模块以 **iframe 挂载**到 `/workspace/{route}`，父子通过 **postMessage** 同步主题与令牌。不做单体合并。

- 外壳 `shell/serve.py`（纯标准库）同源托管 `shell/` 与 `shared/`，并暴露 `/api/auth/*`、`/api/registry`。
- 模块侧由 `shared/ui-kit/ui-kit.js` 的 `initModuleBridge` 建立桥：上报 `cp:ready`，接收 `cp:theme` / `cp:auth`。
- 构建型模块（P01/P02/P03）自带精简桥接垫片（见 0005）。

## 后果

- (+) 各模块保留自身框架与构建链，整合只加一层薄外壳；跨栈「一套系统」可当场演示。
- (+) 挂载与端口解析集中在外壳，模块无需感知彼此。
- (−) iframe 隔离带来跨源限制：postMessage 只能用 `*`（外壳校验 `source==='cp-shell'`），且外壳的 CSP/sandbox 需放行 `allow-scripts allow-forms allow-same-origin`。
- (−) 主题/令牌下发是「尽力而为」的运行时同步，不是编译期强一致；模块离线直开时退回自身默认深色。
