### 结论（本次实测）

- **四个公网入口本次全部不可达：统一返回 `502 Bad Gateway`（nginx/1.24.0），157 字节错误页，无任何业务内容。** 失败即失败，**不能写成「应该可以」**。
- **502 的含义**：HTTP 是通的（服务器上的 nginx 有响应），但 nginx **连不上它要反代的上游**（按仓库部署口径应是 SSH 反向隧道送到服务器回环的 19000–19010）。
- **本机服务是好的**：`127.0.0.1:8800` 实测 200（18ms）；`supervisor.py status` 显示 **15/15 在线**（见第二节）。→ **本机 15 个进程在跑，但公网链路（隧道 / nginx→上游）当前是断的。** （根因属推断：我无法登服务器，**未验证**具体断点，仅据「服务器返回 nginx 502 + 本机 15/15 在线」推断隧道链路未生效。）
- **与仓库文档不一致（如实记录）**：`README.md:309` 与 `_evidence/D25-十模块体检与会议纪要.md` §0 记「2026-10-15 复测正常返回」；**本 D 号于同日 09:54–09:56 实测为 502**。两者不矛盾于「隧道按需开启」——很可能是**隧道当前未启动/已断开**。此处只陈述我实测到的结果。

### 模块前缀规律（先判断，再说明为何本次无法证实）

- **推断的规律**：外壳 / 作品集在 `8070`；模块不在各自端口直连（安全组只放通 8070/8090），而是走 `8090` 的**路径分流**，形如 `http://39.96.200.45:8090/pXX/`，其中 `XX` 即模块编号（`/p06/` 数据中台、`/p01/` 客服、`/p07/` 素材、`/p10/` 微调）。
- **本次无法验证该规律**：七个 URL（含 `/p06/`、`/p01/`、`/p07/`、`/p10/`、以及根 `/`）**响应完全一致（都是同一张 502）**，无法区分「路径正确→上游断」与「路径错误→404」。→ **前缀规律仅为文档声明的约定，未获本次实测证实。**

> **注意：该公网入口并非 7×24 在线** —— 本 D 号于 2026-10-15 09:54–09:56 实测，四个路径（含 8070 与 8090/p06/）**均返回 `502 Bad Gateway`（nginx）**；同时本机 15/15 在线。即「本机能跑、公网链路当前断开」。
> 因此：**演示请以本机为准** —— 双击桌面「李奕波个人作品矩阵 一键启动」或跑 `start-all.bat`，打开 `http://127.0.0.1:8800`。

### 风险提示（务必读）

1. **公网入口用的就是本地种子弱口令账号。** 仓库内已注明演示账号为本地种子（如 `owner / ops / legal / sales / admin`，口令形如 `<用户名>123`），`p05` 截图里甚至明文印着 `Legal@2026 / Apply@2026 / Admin@2026`。**一旦公网入口开着，等于把这套弱口令暴露在公网可达范围。**
2. **隧道工具无自动超时/停机机制。** 按仓库口径 `_tools/tunnel_remote.py` **没有自动过期**，忘记 `stop` 就是**持续暴露**。→ 对外给链接时，务必约定「演示结束立即 `python _tools\tunnel_remote.py stop`」。
3. **README 里该不该给公网入口？**
   - **不建议**在 README 正文以「现在可用」的口吻写死公网链接——本次实测它**就是 502**，写死会与事实冲突（读者点开会看到 nginx 错误页）。仓库首页 `static-site-top.png` 里那段「未做公网部署，不放一个会 502 的假链接」的自我约束，正是这个道理，值得沿用。
   - **推荐**写成「**演示入口（按需开启，可能不可达）**」，并**同时给本机启动命令**（`start-all.bat`）与**同 WiFi 地址**（`http://192.168.1.112:8800`）作为兜底。
   - **口令不要写进 README 正文**：若要给，指向仓库内某处说明，或演示时口头/私信提供；绝不把 `p05` 那张含明文口令的截图放进 README 首屏（见 `SCREENSHOTS.md` 第三节）。
   - **写「演示时段有限」**：如果给公网入口，就应明说「按需开启、演示时段有限、用完即停」，避免把「按需服务的临时隧道」当成「长期在线的产品」展示。
