# 验收门禁与证据规则

## 通用规则

任何功能**声称完成前**，必须：

1. 有**一次真实执行**的证据（启动日志 / 接口返回 / 截图 / 测试输出）
2. 证据落到 `_evidence/pXX/` 目录
3. 在该目录的 `INDEX.md` 登记：**哪条证据证明哪个功能跑通**
4. README 更新对应章节

**跑不通就写"未跑通 + 原因"，不许粉饰。**

## 各模块验收门禁

| 模块 | 门禁 |
|---|---|
| **P01 客服** | 一条命令启动 + 前端可对话；跑通「提问→意图识别→知识检索→生成回复→负面情绪自动建单转人工」；评测脚本出指标报告；50 并发压测出 P95 与错误率 |
| **P02 运营助手** | 登录→选店→生成商品文案→合规检测命中拦截→创建广告实验→查看对比数据；权限验证（客服角色访问老板看板被拒，有 403 证据）；单测+集成测试通过；部署上线可访问 |
| **P03 问数** | 提问→自动出 SQL→执行→生成图表→带溯源报告；恶意 SQL（DROP TABLE）被拦截；**幻觉测试：问库里没有的数据必须拒答而非编造**；前端流式思考链可见 |
| **P04 RAG** | `docker compose up` 起中间件→上传文档→检索问答带引用；评测出**召回率/精确率/拒答率/忠实度**四指标；**做一次策略对比实验**（如父子分块 vs 定长）并给结论；管理后台可预览切片、删除重建 |
| **P05 合同** | 上传 `samples/` 里 4 份合同→抽取→风险打分→生成报告，逐份截图；风险用例被正确识别（如"违约责任不对等"）；审批流走通并留痕；前端页面全部可交互（不再是静态快照） |
| **P06 数据中台** | 一键初始化样例数据→ETL 跑通→指标 API 返回结果；血缘图可视化可交互；质量校验能抓到故意注入的脏数据；**P02/P03 真的调用了本服务指标 API** |
| **P07 素材中心** | 上传素材→打标→以文搜图命中；生成链路可跑（真实或 mock 均可但必须标注）；素材与投放效果关联报表可查看 |
| **P08 直播切片** | 样例视频端到端出片，前后对比截图；打点结果**可解释**（每段给出得分构成）；批量任务队列可用，进度可见 |
| **P09 销售考核** | 导入会话→自动评分→出排行榜与个人报告；规则命中与 LLM 评分可解释可追溯；与人工评分一致性报告可出具 |
| **P10 模型微调** | 至少一次真实训练跑完（哪怕 50 step），有 loss 曲线截图；微调前后评测对比报告（**不许编提升幅度**）；微调后模型可通过 OpenAI 兼容接口调用成功（有 curl 证据） |

## 阶段流程（每阶段必做）

1. **开工前**：输出「本阶段做什么 / 产出什么 / 预计动哪些文件 / 风险点」
2. **执行中**：长任务后台跑；失败就诊断，不绕道、不跳步
3. **收工后**：跑验收门禁 → 采证据到 `_evidence/` → 更新 `INDEX.md` → 输出阶段小结
