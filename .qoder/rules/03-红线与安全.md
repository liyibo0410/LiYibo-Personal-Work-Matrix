# 红线与安全

## 八条红线（违反即视为任务失败）

1. **禁止删除或覆盖** `D:\software\PycharmProjects\` 下的原项目，改造一律复制后重构
2. **禁止编造**任何数据、指标、用户量、性能数字。没有真实测量就写"未测量"
3. **禁止把 mock 冒充真实**。降级实现必须在 UI 与 README **双处**标注
4. **禁止提交真实密钥**。`.env` 必须在 `.gitignore` 内
5. **禁止留死代码**。不留"TODO 待实现"却宣称完成；做一半的功能要么做完，要么明确标注未完成
6. **禁止对外发布**（部署公网 / 推 GitHub / 发邮件）前不确认 —— 这类动作**必须先问**
7. **高风险文件操作**（删除 / 覆盖 / 批量重命名 / 移动大目录）必须：红色警告 → 列受影响路径 → 等确认
8. **禁止为凑数写空壳项目**。时间不够就明确列为"规划中"，不要交假系统

## 磁盘硬约束（本机现状）

```
C: 剩 34G (91%满)   D: 剩 64G (88%满)   E: 剩 73G (29%满)
```

- **禁止**无节制复制大文件、重复安装依赖、下载多个大模型
- 依赖缓存 / 模型权重 / Docker 卷一律指向 **E 盘**（`UV_CACHE_DIR` / `HF_HOME` / npm cache / Docker disk image location）
- 安装依赖前先估算体积；超过 3GB 的操作先报告

## 环境已知坑（本机沙箱）

- 依赖安装优先 `uv sync` / `npm install`，**避免 `npm ci`**（会命中安全删除限制导致失败）
- 构建前若清理失败，先手动清 `node_modules` / `.next` 再构建
- Python 脚本统一加 `-u`；若输出不显示，让脚本**写文件**再读文件验证
- 需要长期驻留的服务（dev server / API）由使用者手动启动，AI 的测试要在**同一次调用内**完成
- PowerShell 命令 stdout 有时不回传，删除类操作用文件系统 API 并在之后二次验证

## 外部动作需确认

以下动作执行前必须获得用户明确同意：
- 部署到服务器 / 公网暴露
- `git push` 到远程仓库
- 发送邮件 / 消息通知
- 修改系统级环境变量
- 修改 Docker Desktop 配置
