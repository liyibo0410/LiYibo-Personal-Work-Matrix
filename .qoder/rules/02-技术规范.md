# 技术规范

## Python 侧

- **包管理强制 uv**：`pyproject.toml` + `uv.lock`；解释器 Python 3.11 或 3.12；禁止裸 `pip install`；禁止 `requirements.txt` 与 pyproject 长期并存
- **Web**：FastAPI + Pydantic v2 + SQLAlchemy 2.0 + Alembic
- **配置**：pydantic-settings 读 `.env`；仓库只留 `.env.example`，**严禁提交真实 Key**
- **分层**：`api/`（路由）`domain/`（领域）`service/`（业务）`repository/`（数据）`infrastructure/`（外部依赖）`tests/`
- **日志**：结构化日志，统一 `trace_id` 贯穿请求；禁止 `print` 调试残留
- **错误处理**：统一异常基类 + 全局异常处理器；错误码文档化
- **测试**：pytest，核心链路必须有集成测试，输出真实覆盖率数字

## 前端侧

- **框架**：Next.js 14+ App Router（旗舰/门户/shell）+ Vite+React（轻量模块）
- **样式**：Tailwind CSS；**统一深色主题**
- **配色**：深灰底（如 `#0B0E14`）+ **单一强调色**（青 / 蓝系）；禁止粉紫俗套配色
- **动效**：克制 —— 仅 hover、页面切换、加载骨架屏；禁止炫技动画
- **组件**：统一用 `shared/ui-kit`；图表统一 ECharts 深色主题
- **响应式**：门户与旗舰必须移动端可用

## AI 侧

- **统一入口**：所有模型调用走 `shared/llm-gateway` —— 统一模型切换、重试、超时、成本统计、**无 Key 自动降级 mock**
- **端点配置**：主力与备用双端点，**必须实现自动故障转移**
- **Prompt 管理**：prompt 与代码分离，放 `prompts/` 目录并版本化，禁止硬编码在函数里
- **结构化输出**：优先 function calling / JSON schema 校验，禁止裸解析 LLM 文本
- **可观测**：每次调用记录 token 与耗时，可在看板查看
- **RAG 质量**：必须带引用；检索不到要能**拒答**
- **评测**：每个 LLM 应用都要有评测集与评测脚本，**没有评测的 AI 功能视为未完成**

## 工程化

- 能 docker 化的提供 `Dockerfile` + `docker-compose.yml`
- 每个项目根目录提供 `start.bat`（Windows 友好）+ README 启动说明
- 每个项目独立 git 仓库，提交信息规范（feat / fix / docs / refactor）
- **README 模板**（每项目必含，内容必须真实）：
  1. 一句话定位 2. 业务痛点 3. 架构图（Mermaid）4. 技术栈与选型理由
  5. 快速开始 6. API / 功能清单 7. 演示脚本 8. 量化指标
  9. 已知限制与 mock 边界 10. 面试问答 10 条
