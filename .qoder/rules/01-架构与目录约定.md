# 架构与目录约定

## 四层企业架构

```
L3 应用层：P01 AI电商客服  P02 电商运营助手★  P05 合同审批  P09 AI销售考核
L2 能力层：P03 NL2SQL 问数   P04 RAG 知识库  P07 AI 素材中心  P08 直播切片
L1 模型层：P10 模型微调平台（数据→训练→评测→部署）
L0 数据层：P06 数据中台（接入/数仓分层/指标口径/血缘/质量）
        ↑ 全层共用 shared/：llm-gateway · config · logging · auth · ui-kit
```

## 数据流闭环（必须能演示）

```
电商/客服数据 → P06 数据中台 → P04 知识库 / P07 素材中心
    → P01 客服 / P02 运营 用能力生成内容
    → P09 销售考核 消费 P01 会话数据 → 产出质检评分
    → 低分样本回流 P10 微调 → 新模型回到 P01/P02
```

## 最终形态：统一系统（四统一）

最终十个模块合并为**一套系统**，必须从第一天就遵守：

| 统一项 | 要求 |
|---|---|
| 认证 | 共用 JWT/Session，`shared/auth` 提供签发与校验，各模块只校验不自己实现登录 |
| 用户与权限 | 统一用户表，角色→模块→操作 三级 RBAC，各模块复用 |
| LLM 网关 | 所有模型调用走 `shared/llm-gateway`（多端点故障转移 + 成本统计 + mock 降级） |
| UI 规范 | `shared/ui-kit` 提供主题变量与组件，禁止各模块自造一套 |

**统一入口路由**：`/workspace/{customer-service | ecommerce-ops | research | knowledge | contract | data-platform | asset-center | live-clip | sales-assessment | finetune}`

**整合技术选型**：采用**微前端外壳**（`shell` 用 Next.js 提供登录/导航/主题，各模块以 Module Federation 或 iframe + postMessage 挂载），不做单体合并。

## 跨模块调用约定

- 服务间调用统一走 `http://127.0.0.1:<port>/api/v1/...`，端口从 `shared/config` 的 `SERVICE_REGISTRY` 解析，**禁止硬编码其他模块端口**
- 跨模块取数（P02 取 P06 指标、P09 取 P01 会话）必须走**真实 HTTP 调用**，并在 `_evidence/` 留调用日志
- 前端跨模块通信只用 postMessage / 自定义事件，禁止直接操作其他模块 DOM

## 改造原则

- 原项目**不删除不覆盖**，复制到 `projects/` 后重构
- 每个项目 README 写清「源项目路径 + 改造内容清单」
