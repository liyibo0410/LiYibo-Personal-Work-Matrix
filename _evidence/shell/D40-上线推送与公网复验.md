## 四、复验挖出的两个真 bug（均已修 + 复验）

### Bug 1 · 公网深链接竞态：iframe 指到服务器上不存在的端口

**现象**：直接打开 `http://39.96.200.45:8070/#/workspace/data-platform`，
iframe `src = http://39.96.200.45:8060/?cp-theme=light`（**裸 web_port**），公网页白屏。

**根因**（`shell/index.html`）：

- `webUrl(id)`：`if(!IS_LOCAL && s.public_url) return s.public_url;` 否则兜底 `http://<host>:<web_port>`
- `s.public_url` **只由 `pollHealth()` 回填**（`/api/services/health` → `_runtime/tunnel/public_urls.json`）
- 深链接直达时，**首次 health 尚未返回就 mount 了** → 走兜底端口；且 health 回来后只重绘首页矩阵，**不会修已挂载的 iframe**

**修复**：`pollHealth()` 成功分支里，回填 `public_url` 后若当前正挂着模块 → `mountModule(currentId)` 重挂一次到正确映射（本地 `IS_LOCAL=true` 分支完全不受影响）。

**复验**：同一条深链接重跑 → `frame.src = http://39.96.200.45:8090/p06/?cp-theme=light` ✔，截图 P06 正常渲染 ✔。

### Bug 2 · `shot.py` 注入撞上「错误页 / hash 路由初始化」

**现象**：`--shell-login` 注入 `sessionStorage` 抛
`SecurityError: Failed to read the 'sessionStorage' property from 'Window': Access is denied for this document.`

**根因**：注入那一刻文档是**首载 502 错误页**或**正在被 hash 路由替换**（detached document），读写 Web Storage 必然被拒；原逻辑只试一次，失败就带着空令牌 reload。

**修复**（`_tools/shot.py`，`capture()` 内）：注入失败 → `Page.reload` → `wait_load` → 重试，**最多 3 次**；成功仍按原逻辑 reload 让注入态生效。纯增量改动，不改成功路径。

**复验**：注入 `ok (undefined)`、`tokLen=227`、`cp_user={"username":"owner",…}`。

## 十三、服务器 nginx 加固（用户确认后执行，16:2x）

AGENTS 里「`location /` 漏 `proxy_set_header Host`」的记录**已过时**：现场核查 `/etc/nginx/conf.d/cloudpivot-demo.conf`，
每个 location 都已有 `proxy_set_header Host 127.0.0.1:190XX;`（13:41/13:43 的 `.bak-route` 备份，并行角色做路由升级时所写）。
且**不能换成 `$host`** —— 30x 前缀保留靠 `proxy_redirect` 正则匹配 `127.0.0.1:190XX` 开头的 Location（`$host` 无端口，匹配不上会弄坏它）；
而我们全部后端（http.server / FastAPI / Next / Vite）都不依赖 Host。

真正让访客难受的是**首载偶发 502**（SSH 隧道瞬断，nginx 对单 upstream 无从重试，MCP 浏览器与无头 Edge 首载各撞过一次）。
按此实修（`_tools/nginx_hostfix.py`，在服务器上运行，先备份 `*.bak-hostfix-20261015162612` 再改，`nginx -t` 通过才 reload）：

| 改动 | 内容 |
|---|---|
| 同址双 peer | `19000..19010` 各建 `upstream cp_u_190XX`（同一地址写两条）+ `proxy_next_upstream error timeout http_502 http_503 http_504` + `tries 2` / `timeout 6s` —— 首个瞬时失败自动重放，访客不再看到 502 |
| WS/keepalive 兼容 | `map $http_upgrade $cp_conn`（WS→upgrade，普通→空）替换写死的 `Connection "upgrade"`，普通请求可复用连接（`keepalive 8`） |
| 快速失败 | `proxy_connect_timeout 3s`：隧道真断时不让访客干等默认 60s |
| 刻意不动 | `Host` 字面量、`proxy_redirect` 正则、`$cp_route` 兜底 location（变量 upstream 本就不重试，语义不变）、服务器上其他任何配置 |

**复验（reload 后即时）**：服务器侧 `8070`×12 / `8090/p06/`×6 / 兜底路由 `tokens.css`×3 全 200；
访客侧公网 **11/11 = 200**、`8070` 连打 8 次全 200。备份留存于服务器同目录，回滚即 `cp` 回去 + reload。
