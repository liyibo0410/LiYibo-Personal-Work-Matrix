## 四、复验挖出的两个真 bug（均已修 + 复验）

### Bug 1 · 公网深链接竞态：iframe 指到服务器上不存在的端口

**现象**：直接打开 `http://39.96.200.45:8070/#/workspace/data-platform`，
iframe `src = http://39.96.200.45:8060/?cp-theme=light`（**裸 web_port**），公网页白屏。

**根因**（`shell/index.html`）：

- `webUrl(id)`：`if(!IS_LOCAL && s.public_url) return s.public_url;` 否则兜底 `http://<host>:<web_port>`
- `s.public_url` **只由 `pollHealth()` 回填**（`/api/services/health` → `_runtime/tunnel/public_urls.json`）
- 深链接直达时，**首次 health 尚未返回就 mount 了** → 走兜底端口；且 health 回来后只重绘首页矩阵，**不会修已挂载的 iframe**

**修复**：`pollHealth()` 成功分支里，回填 `public_url` 后若当前正挂着模块 → `mountModule(currentId)` 重挂一次到正确映射（本地 `IS_LOCAL=true` 分支完全不受影响）。

**复验**：同一条深链接重跑 → `frame.src = http://39.96.200.45:8090/p06/?cp-theme=light` ✔，截图 P06 正常渲染 ✔。

### Bug 2 · `shot.py` 注入撞上「错误页 / hash 路由初始化」

**现象**：`--shell-login` 注入 `sessionStorage` 抛
`SecurityError: Failed to read the 'sessionStorage' property from 'Window': Access is denied for this document.`

**根因**：注入那一刻文档是**首载 502 错误页**或**正在被 hash 路由替换**（detached document），读写 Web Storage 必然被拒；原逻辑只试一次，失败就带着空令牌 reload。

**修复**（`_tools/shot.py`，`capture()` 内）：注入失败 → `Page.reload` → `wait_load` → 重试，**最多 3 次**；成功仍按原逻辑 reload 让注入态生效。纯增量改动，不改成功路径。

**复验**：注入 `ok (undefined)`、`tokLen=227`、`cp_user={"username":"owner",…}`。
