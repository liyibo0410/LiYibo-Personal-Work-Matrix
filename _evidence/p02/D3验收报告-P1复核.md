## 三、P1 修复的 3 个问题

### 🔴 问题 1：批量替换破坏字符串定界符（你已发现的那个）

`creative_plans.py:464`（规则兜底路径）：

```python
# 错误
return unique_points or ["核心卖点“, ”使用效果“, ”购买理由"]
# 正确
return unique_points or ["核心卖点", "使用效果", "购买理由"]
```

**为什么危险**：语法上侥幸合法（中文引号在 ASCII 双引号内部），但语义完全变了——
原本 **3 个独立卖点** 变成 **1 个含乱码引号的字符串**。

**影响面**：这是「规则兜底路径」。当 LLM 不可用（未配置 key / 调用失败）时会走这条分支，
产出错误的卖点数组。因为 fallback 是"保底不白屏"的设计，问题会**静默发生**。

**修复**：恢复 ASCII 双引号。已验证：兜底返回 `['核心卖点', '使用效果', '购买理由']`，数量 3 ✅

**全量扫描确认**：破坏范围**仅此 1 处**。
（`llm.py` 里出现的 `“输入归一化 → 业务校验 → 状态或持久化”` 是注释，无害；
新增的 `compliance.py` / `run_compliance_eval.py` 零污染。）

### 🟠 问题 2：`matched_text` 返回归一化文本，不是原文（Qoder 未发现）

原实现 `matched_text=norm[ns:ne]`，导致：

| 原文 | `matched_text` 返回 | 问题 |
|---|---|---|
| `最\u200b好` | `最好` | 中间零宽字符被吞 |
| `最\u3000好` | `最 好` | 全角空格变成了半角空格 |
| `苐一`（形近字） | `第一` | 变成了另一个字 |

**为什么危险**：`span` 是精确的（`pos_map` 回标正确），但前端若用 `matched_text`
去原文里查找以做高亮，**会全部失配**。属于"埋着未爆"——现在没前端所以没暴露，
一旦做前端高亮就会踩。

**修复**：改为 `matched_text = text[orig_start:orig_end]`（原文切片）。
这样 `原文[span[0]:span[1]] == matched_text` **恒成立**，前端可放心用 span 切原文。
新增显式入参 `text` 给 `_check_rule`。

### 🟡 问题 3：词库缺口导致 1 条用例漏检

评测用例 TC-0027（`用户评价：这是我用过最满意的产品`）期望 `review`，实际 **`pass` 完全漏检**。

**根因**：词库只有 `最好`、`最佳` 等固定词，缺"最+形容词"这一类（最满意/最划算/最实惠）。

**修复**：补 2 条正则规则
- `ABS-0025`（medium）：`最[满意划算实惠便宜好用实用快省值赞棒放心靠谱合适优秀出色]`
- `ABS-0026`（high）：`最[厉害牛强棒绝top]`（口语化强断言）

**修复后**：评测集 **36/36 全部一致**。
