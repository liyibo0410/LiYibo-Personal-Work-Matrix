## 2. 缺陷明细（现象 / 复现 / 证据 / 严重度 / 疑似根因 / 建议修法）

### H1（高）P10「开始训练」在小数据集 500 且前端静默
- **现象**：选 ds-102（上传 4 条）或 ds-101（P09 回流 22 条）点「开始训练（演示）」：接口 500，界面无弹窗无提示，仿佛没点过。
- **复现**：① UI：数据集页→训练页→选 ds-102→点开始训练 → 6s 后无任何变化；② 直接 `POST /api/v1/training/start {dataset_id:"ds-101"}` → **HTTP 500**（2026-10-15 09:52 实测）；③ 大数据集 ds-001 正常成功（train-103）。
- **证据**：服务端 traceback（`p10.log`）`app/main.py:265 in _generate_loss_curve: if step % (total_steps // 5) == 0` → `ZeroDivisionError: integer modulo by zero`；UI 记录 agent6-20b；`agent6-p10b-log.json`。
- **根因**：`total_steps = ceil(sample_count/32)*epochs`，样本 ≤32 时 total_steps=3 < 5 → `total_steps // 5 == 0` 做除数；且前端 `startTraining()` 只有 `if (resp.ok)` 分支，非 2xx 完全吞掉。
- **修法（一句话）**：`_generate_loss_curve` 用 `eval_every = max(1, total_steps // 5)`（或加 `total_steps >= 5` 守卫），同时 `startTraining` 在 `!resp.ok` 时 alert/内联显示后端 detail。

### H2（高）任务清单声称的 4 个「新增按钮」实机不存在（数据面闭环成立、UI 面缺失）
- **现象**：P09 无「导入会话(从P01)」「发起评分」「导出低分样本」；P10 无「从 P09 拉取低分样本」（顺带：无「注册模型」按钮）。
- **复现**：全页按钮枚举 + 正文搜索（agent6-01 / agent6-32 记录）；09:21 与 09:52 两次核对 `served HTML hash == disk file hash`（400E95…/C5AC2F…），文件 mtime 仍为 2026-10-15 01:01/01:02——期间无新版本落盘。
- **证据**：截图 agent6-01/16/32；`agent6-p09-log.json`；P10 数据集列表已有 `ds-101`（昨日 API 级拉取 22 条）证明底层闭环曾经真实跑通；`_evidence/D25` L141 亦记载按钮「只到接口层」。
- **根因**：属于未完成的接线（或另一窗口尚未落盘），非运行时故障；对应 API 全部存在且健康（X2–X5 探针）。
- **修法（一句话）**：在 P09 会话列表/看板加「从 P01 导入」「导出低分样本」、P10 数据集页加「从 P09 拉取」按钮（3 个 fetch 调用直连已有端点即可）。

### M1（中，= H3）P10 模型仓库「训练曲线」死按钮
- **现象/复现**：模型仓库页点任意模型卡「训练曲线」→ 页面无任何变化；切到「训练」页后曲线却突然出现（上一次点击的残留）。
- **证据**：agent6-29（`inline display=block, 实际可见=false, 被隐藏于非激活页=page-training`）、agent6-30（切页后可见+canvas=1）；截图 28/29/30。
- **根因**：`#loss-card` 位于 `#page-training` 容器内，而 `.page:not(.active){display:none}` 让其不可见；`showLossCurve` 只改了卡片自身 inline 样式。
- **修法**：把损失曲线卡片移出训练页容器（或改弹窗），或在模型页点击后显式 `navigate('training')` 再展示。

### M2（中）新建训练不出现在「训练历史」/「最近训练」
- **现象/复现**：成功创建 train-103 后（弹窗给出 ID），训练历史仍只有 train-001/002；总览「最近训练」恒 2 行；`stats.training_runs` 已变 3。
- **证据**：agent6-22 / agent6-31（history rows=2, 含新任务=false）；agent6-14（stats=3, rows=2）。
- **根因**：`loadTraining()` 与 `loadDashboard()` 都硬编码 `['train-001','train-002']`；后端也无列表端点（只有按 ID 查询）。
- **修法**：后端加 `GET /api/v1/training` 列表端点，前端按真实列表渲染。

### M3（中）训练页首访数据集下拉为空 →「开始训练」静默失败
- **现象/复现**：直接进训练页（或深链 #training）时 `#train-dataset` 无选项（仅访问过数据集页才会被填充）；此时点开始训练：404 + 零提示。
- **证据**：agent6-15（options=0；点击后无弹窗无变化）；配合 H1 的静默机制。
- **根因**：`#train-dataset` 只在 `loadDatasets()` 里填充，训练页 init 不拉数据集；`startTraining` 无失败分支。
- **修法**：训练页 init 调用 loadDatasets 填充；提交前校验 `dataset_id` 并给出可读错误。

### M4（中）P09 回流数据集（真实测得 22 条）被误标为「预置演示数据」
- **现象/复现**：数据集列表 ds-101 行带「预置」tag（tooltip 称非实测）；详情页样本数 "22*"，底部图例称「provenance=seed_demo」——实际 provenance=`p09-export`、`measured_fields=["sample_count"]`（真值）。
- **证据**：agent6-16 / agent6-17 截图与记录；`GET /api/v1/datasets` 响应字段。
- **根因**：前端只按 `provenance === 'measured-from-upload'` 判星号/tag，未消费 `measured_fields`；图例文案把 seed_demo 当唯一非实测来源。
- **修法**：星号/预置 tag 由 `measured_fields` 决定（含 sample_count 即不标预置），图例按 provenance 逐类说明。

### M5（中）模型仓库指标呈现实测口吻（无模拟标注）
- **现象/复现**：3 张模型卡直接展示 84.7%/96.3%/4.12 等指标，无任何「模拟」字样；接口里明明带 `simulated:true` 与 `metrics_note`（"metrics 为模拟评测值…不是实测准确率"），UI 未呈现；模型页也无横幅。

- **根因**：`loadModels()` 模板只渲染 metrics 数值，忽略 `metrics_note`。
- **修法**：指标块下渲染 `metrics_note`（或加 ⚠模拟 tag），与评测页口径一致。

### M6（中）训练页无模拟横幅、损失曲线卡无 provenance 标注
- **现象/复现**：训练页顶部无横幅（对照：总览有横幅、评测页有显式说明）；损失曲线卡仅标题与关闭按钮；训练历史「最终损失 0.3894/0.3826」无模拟标记。按钮「开始训练（演示）」与成功弹窗的「模拟演示，未真实训练」是仅有的两处标注。
- **证据**：agent6-21（卡片文本「损失曲线 关闭」）、agent6-31（弹窗文案）；截图 21/31。
- **根因**：`showLossCurve` 未消费接口返回的 `simulated/provenance/curve_note`；训练页未放横幅。
- **修法**：曲线卡加「simulated · 模拟生成，不是训练日志」角标（直接用 curve_note），训练页补同款横幅。
