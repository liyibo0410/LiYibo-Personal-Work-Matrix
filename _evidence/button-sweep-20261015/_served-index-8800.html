十个 AI 能力模块，跑在同一套电商运营中台里

做给品牌电商与 MCN：数据中台定口径，能力层供弹药，四条业务线组装落地，低分样本回流微调层。 十个模块共用一份服务注册、一套设计令牌、一个登录入口，可以在同一台机器上连着操作，不是十个互不相干的 demo。

本页每个指标都能在 _evidence/ 找到对应的日志或截图；没测过的（并发 P95、覆盖率）就明写「未测」。

十大能力模块 · 四层架构

自下而上读：L0 定口径，L1 沉淀模型，L2 把能力做成可调用的服务，L3 组装成业务线。每张卡三行硬信息 —— 技术选型、实测数字、Mock 边界（真实到哪一步、哪里是模拟）。灰点是网关对各端口的真实 TCP 探活，不是写死的「已运行」；没起来的模块会给一条可复制的启动命令而不是一个空白 iframe。

一条数据闭环，六个工程决策

闭环的意义是口径只有一份：同一个「GMV」在数据中台、运营看板、销售考核里算的是同一个数；低分会话回流微调层，新模型再回到 P01 / P02 的回复里。下面六条 ADR 是这套合并形态里最需要交代清楚的决策，每条都连同代价一起写 —— 收益谁都会讲。

P06 数据中台→ P04 知识库 / P07 素材→ P01 客服 / P02 运营→ P09 销售考核→ P10 微调↺
入口 · ADR-0001
微前端外壳 + iframe 挂载，不做单体合并。三类前端栈异构（Next.js / Vue 3 + Vite / FastAPI 直挂静态页），合并等于重写四个前端；代价是主题与令牌只能运行时尽力同步。
认证 · ADR-0003
外壳用 shared/auth 签发 HS256、postMessage 下发，模块只校验不重造登录。P02 保留自身 Cookie RBAC —— 改它会绕过它已有的权限模型，这是有意识的例外。
端口 · ADR-0002
SERVICE_REGISTRY 是端口唯一真源，跨模块调用禁止硬编码对方端口。起因是一次真实故障：P03 前端把后端写成 8000，实为 8030，平台内直接不可用。
取数 · ADR-0004
P02→P06、P09→P01 真实 HTTP。降级态用「少返回」而不是「编一个」：degraded=True 且响应里直接不含 metrics 字段。
视觉 · ADR-0005
ui-kit 令牌单一真源。静态模块运行时挂 /shared，构建型模块构建期内联 + 主题桥；代价是改色后必须重新构建才生效。
例外 · ADR-0006
P05 只用标准库：客户机 python run.py 即跑，不必先装 Docker。风险打分要的是确定性与可复现，这一点比「栈统一」更重要。

结论：私有化不是免费的。先修掉本地重排的量纲缺陷（logits 未归一 → 断崖截断把正分文档静默砍掉， 这是修 bug 不是调参），重跑后本地 5 项指标仍全面低于云端（Context Precision 差 23.8 pp）、平均延迟慢 2.7 倍， 换来的是敏感文档零出网。所以这一题没有「哪个数字更好看」的答案 —— 看客户的数据合规要求把哪条线划死， 我把两端都跑出来，是为了让那个选择有依据。

真实 / 模拟边界

交付里最容易翻车的不是功能少，是「演示能跑、上线不跑」。所以每个模块我先把线划死：哪条链路是真的、哪里是模拟、以及为什么在这一处主动选模拟。同样的话在各模块的 UI 标注、接口字段与 _evidence/ 里都能对上（如 P08 的 /health 自陈 mock_boundaries、P10 的 endpoint_url: null）—— 双处标注是硬规则，不是写给人看的装饰。

P01 客服 真实：意图三轨道、对话状态机、FAQ/RAG 文本层检索（种子知识，命中不足拒答，73 单测）。未实现：负面情绪自动建单转人工。模拟：订单与商品来自随附的 mock 商城中台 :18081。
P02 运营 真实：登录、RBAC、合规、广告实验、跨模块取数全链路。降级：无 Key 时网关降级 mock 生成，前端标「演示」。
P03 问数 真实：只读 SQL 护栏（DROP/多语句/注释绕过全拦）、执行链路，模型层已接通。未闭环：MySQL(3306)/RAGFlow(9380) 未启动、联网搜索仍是 mock Key；库里没有的数据会明确拒答。
P04 知识库 真实：入库/检索/重排/评测，BGE-M3 本地嵌入 + 本地或云端重排双后端。已修：MCP 联网搜索曾恒 0（异常被静默吞掉）。
P05 合同 真实：规则风险判定、审批流、报告。刻意设计：审批「模拟回写」子系统；LLM 二阶段默认 enabled=false。
P06 数据中台 真实：DuckDB 分层与指标计算。演示数据：自动 seed 的样例集，不是真实店铺。
P07 素材 真实：打标、素材×投放关联报表。模拟：以文搜图用 TF-IDF 而非 CLIP；生图为 mock，UI 挂「Mock 模式」。
P08 切片 真实：批量队列与进度、四维得分构成可解释。模拟：ASR 为模拟文本、评分为规则，无 ffmpeg 真实出片。
P09 考核 真实：会话导入、评分与排行榜。模拟：评分器是规则引擎（Mock LLM），页面挂 Mock Notice。
P10 微调 真实：数据集→训练→评测→注册表生命周期编排、接口与状态机。模拟：未真实训练（无 GPU 余量），loss 曲线由公式生成；没有可调用端点（部署仅登记状态，endpoint_url 返回 null），无测量来源的延迟/统计一律为 null —— 页面、接口与 README 三处标注。

没有测过的数字就不写。全平台未做并发压测（无 P95 / 错误率）、未测覆盖率； P10 的四条微调门禁（真实训练 / loss 曲线 / 前后评测对比 / 可调用端点）全部为空，接口里没有测量来源的字段一律返回 null； P09 的人机一致性 Kappa 要真人评满 ≥5 条才出数 —— 早先用「AI 分 + 随机噪声」冒充人工分的代码已删除，这一项宁可空着。
