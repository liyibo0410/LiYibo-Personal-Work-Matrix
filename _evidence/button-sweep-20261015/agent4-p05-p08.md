## 🔴 P0（置顶）：P05 四大页面整页不可用 —— `app.js` 加载即抛 TDZ 异常

**现象**：P05 的 `/`（大盘）、`/workbench`（工作台）、`/twin`（孪生看板）、以及 admin 下的 `/rules`（规则库）打开后：顶部导航不渲染、统计卡/任务表/风险清单/图表全部空白，**任何按钮点了都没有反应**（弹窗不打开、无 toast）。登录页 `/login`、`/mock`（模拟审批）、`/denied`（403 页）不受影响。

**复现（本地/公网同源同码，两边一致）**：
1. 打开 `http://127.0.0.1:8770/login`（或公网 `/p05/login`）→ 一键进入（legal/admin）→ 落到 `/`；
2. 观察 console：
   - `Uncaught ReferenceError: Cannot access 'CFX_ENTER_SEL' before initialization`
   - 随后 `CR is not defined`（页面各初始化调用连锁失败）
3. 评估 `typeof window.CR === "undefined"`、`#stats .stat` 数量 = 0、`#topbar` 为空。

**证据**：截图 `agent4-05`（公网大盘空白）、`agent4-06/07`（复验）、`agent4-08`（本地大盘）、`agent4-11`（admin 规则页空白）、`agent4-12`（工作台空白）；记录行 `rows#6,7,9,10,11,13,16,17,18,63,64,65`。

**疑似根因（已定位到行）**：`ui/index.html` / `workbench.html` / `twin.html` / `rules.html` 在 10-14 20:45~21:34 的未提交改动里把外链脚本全部改成了 `<script defer …>`（mock.html 未改、仍是同步脚本，所以它是好的）。Chromium 中 **defer 脚本执行时 `document.readyState` 已是 `'interactive'`**（实测：parse=loading → defer=interactive），于是 `ui/assets/app.js:580` 的 `if (document.readyState === 'loading')` 判否，走 `else` 分支（`:585-588`）**立即**调用 `cfxEnter()`；而它依赖的 `const CFX_ENTER_SEL`（`:593`）此刻还没初始化（TDZ）→ 抛错中断整个 IIFE → `global.CR`（`:768`）永不赋值。同步脚本时代 readyState=loading，走 DOMContentLoaded 回调，所以从未暴露。

**建议修法（一句话）**：把 `CFX_ENTER_SEL / CFX_LIFT_SEL / CFX_BEAM_SEL / CFX_PREV` 四个 `const` 上移到 `initTheme()` 初始化段之前（或把 `else` 分支改为 `document.addEventListener('DOMContentLoaded', …)`），让 defer 时序下也不再 TDZ。

**影响面**：不仅 P05 直连页，外壳 iframe 挂载 `/p05/` 也必然复现（同一份 HTML）。这是当前 P05 演示的**唯一阻断点**：其余引擎能力（审查/回写/报告/自检）经接口层实测均正常，见下。

## 三、缺陷明细

### D1【高 / P0】P05 四大页面整页不可用（defer 时序 → TDZ 崩溃）
见本报告顶部置顶章节。建议修法：`CFX_*` 四个 const 上移到初始化调用之前（或 else 分支改用 DOMContentLoaded 回调）。

### D2【中】P05 本地上传合同的「写回审批单」永远失败（拉取件正常）
- **现象**：上传审查完成 → 「写回审批单 / 重试回写」→ `回写失败：审批实例不存在：FS-AP-LOCAL-2`；`回写状态=failed`，审批评论区为空。
- **复现**：applicant 上传 `01_软件采购合同_风险用例.docx`（标题 UI测试-可删）→ legal 下 `POST /api/cases/2/writeback {mode:live}` ×2 → 均失败；`GET /mock/feishu/api/todo` 中无 `FS-AP-LOCAL-2`。对照：对既有拉取件（FS-AP-05/06）同调用即成功（`CMT-05-001`/`CMT-06-001`），幂等也正常。
- **证据**：rows#86,87,88,104,105。
- **疑似根因**：`app/writeback.py:ensure_instance` 只在 `approval.base_url` 为空时调用 `feishu.ensure_instance()` 真正登记；演示配置把 `approval.base_url` 指到自身 HTTP 模拟端（health 里 `approval_channel=approval_http`），导致上传合同只生成了个「虚拟实例号」而模拟系统里没有它。
- **建议修法（一句话）**：`ensure_instance` 在 base 非空时同样向 `{base}/instances` 登记（或对本机 mock 端点统一走内置 `feishu.ensure_instance`）。

### D3【低】P05 自检的「模式对照」项与实际运行口径矛盾（易误读）
- **现象**：`/api/selftest`（66/66 通过）其中一项输出「当前模式=规则引擎模式（available=False）；未启用原因：未配置 llm.base_url」；而同一进程内新审查的案件显示 `mode_info.base_url_set=true / key_present=true / verify.source=llm`（真实调用 `qwen3.8-flash`，3 条命中复核 confirm 2 / need_human 1，摘要 `summary_source=llm`）。
- **证据**：rows#77,83,90。
- **疑似根因**：自检项构造配置时未复用 boot 时由 .env 解析好的运行时配置（该项实际在演练「未配 Key 降级」路径，但 detail 文案像在描述系统现状）。
- **建议修法（一句话）**：detail 文案改注「降级路径演练（当前运行时已启用）」，或让自检读取运行时生效配置。

### D4【低 / 提示】P05 公网入口 URL 落在 `/login?next=/`（不带 `/p05` 前缀），靠 `cp_mod` 单值 cookie 分流
- **现象**：`GET /p05/` → 302 `Location: /login?next=/`；浏览器带 `cp_mod=p05` 时 nginx 把根级 `/login`、`/assets/*`、`/api/*` 都分流回 P05，功能正常；但**无 cookie 的裸请求（curl/爬虫/直链）会 404**，且同浏览器后访问过其它模块（cookie 被改写为 cp_mod=其它）后根级请求会串台。
- **证据**：rows#1,5；curl 实测（无 cookie：`/login`→404 `{"ok":false,"error":"资源不存在：/login"}`）。
- **建议修法（一句话）**：给出入口页时在重定向里保留前缀（`/p05/login?next=/p05/`）或输出带前缀的导航，避免依赖单一 cookie。

### D1'【中】P08 「批量任务」无开始/暂停/继续，任务即时 100% 且不产出任何东西
- **现象**：任务书预期的「创建任务、开始/暂停/继续、批量队列、进度展示」中，只有「创建」存在；`POST /api/v1/process` 硬编码 `status=completed, progress=100`；`clips_generated` 取的是这些直播**既有**切片数（15），不是本次运行产出；页面无轮询，进度不会变化。
- **证据**：rows#41,42,46,47；`app/main.py:625-648`。
- **建议修法（一句话）**：要么补「假进度」后台推进 + 前端轮询并标注为演示模拟，要么在任务页明写「Mock：任务即时完成、不产出文件，数字为既有切片统计」。

### D2'【低】P08 四维得分中 energy/speech_rate/interaction 为 `hash(text)` 伪随机，明细区未就近标注
- **现象**：关键词密度来自文本命中（可解释），但能量/语速/互动三项与文本内容无关（`app/main.py:231-235` 用 `hash(text[:30]) % 100` 派生）；页面级（侧栏/health/转写区）已标注模拟，但「评分理由/评分明细」区没有一句话说明。
- **证据**：rows#39,40。
- **建议修法（一句话）**：在评分明细标题或 explanation 尾部加「能量/语速/互动为模拟值（非音频分析）」。

### E1【中 / 环境】公网 502（时段性）
- **现象**：2026-10-15 09:42—09:57，`http://39.96.200.45:8090/p05/*` 与 `/p08/*` 全部 502 Bad Gateway（含 /health、/api）；本地 8770/8080 全程 200；09:31 时段公网 P05 还是好的（有截图与登录证据）。
- **证据**：rows#19,110,111；agent4-13/14（502 截图）；curl 09:43/09:54/09:57 三次复测。
- **建议**：隧道加健康巡检 + 自愈（或演示前跑一遍 `/p05/login` `/p08/` 探活），并在演示页放「链路抖动重试」提示。
