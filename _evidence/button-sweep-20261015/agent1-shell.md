## 0. 置顶结论（演示事故级扫描）

**外壳自身未发现 P0 级演示事故**：登录、作品集首页、十条模块挂载（本地）、主题、退出、品牌/材料面板、深链在测试时刻均可用。

三条需要向上汇报的非外壳问题（详见「缺陷明细」）：

1. **公网链路在测试期间多次抖动**（09:40 通 → 09:45–09:52 全站含外壳 502 → 10:02 恢复 → 10:12 部分模块超时）。与平台侧文档（AGENTS.md「09:40 通 / 09:54 全 502」）互相印证，**属隧道/反代环境问题，不是外壳缺陷**。
2. **`127.0.0.1:8800` 本地入口被外壳误判为「非本地」**（`IS_LOCAL` 正则含 `$` 锚点，`127.0.0.1` 不匹配）→ 外壳挂载的 iframe 指向**公网隧道 URL**；隧道一断，**本地演示全线白屏/502**（实测复现），且与服务横幅文案互相矛盾。严重度：**中**（仅影响 127.0.0.1 本地入口；公网访客不受影响；`localhost:8800` 正常）。
3. **P02/P04/P05 在公网子路径下的「重定向后文档」依赖 nginx 就地把 `/login`、`/console.html` 路由到位**（模块发的是根绝对跳转）——10:09 时恰好能落到对应应用并渲染，10:11:53 复测 `/login` 已回落成外壳的 404。属**部署/模块侧脆弱性**，会随 nginx 配置来回变化，疑似（见缺陷 D6）。

## 3. 缺陷明细

> 严重度定义：高 = 阻断演示主流程；中 = 破坏一种入口/环境或误导；低 = 文案/噪音/体验。

### D1 · `127.0.0.1` 本地入口被误判为「非本地」，iframe 全指向公网隧道 URL —— **中**

- **现象**：本地打开 `http://127.0.0.1:8800`，已登录后点任一模块，iframe `src` = `http://39.96.200.45:8090/pXX/?cp-theme=…`（公网地址）；隧道一断，本地演示**整排模块白屏/502**（实测 09:46–10:01 期间），而服务在本机明明是好的；同时右下角服务横幅却说「服务没有在监听 127.0.0.1:8041」（文案与 iframe 地址互相矛盾）。
- **复现**：`127.0.0.1:8800` 登录 → 点 p01 → 读 iframe.src = 公网 URL（`agent1-shell-44`）；同一时刻改用 `localhost:8800` → iframe.src = `http://localhost:5173/…`（正常）。
- **证据**：`agent1-shell-44-127001-iframe-points-to-public.png`、`32`–`37`（经 127.0.0.1 挂公网 URL 的 502/空白）、`45`–`49`（localhost 全好）、`p3-fatal.json` / `p3b-result.json`。
- **疑似根因**：`shell/index.html:603` 的 `IS_LOCAL` 正则 `/^(127\.|localhost|\[::1\]|0\.0\.0\.0)$/` **带 `$` 锚点**，`127.0.0.1` 整串不匹配 → 被判为非本地 → `webUrl()`（:606-608）在 `_runtime/tunnel/public_urls.json` 存在时优先返回公网 URL。（`localhost` 恰好整串匹配，所以换写法就正常——这正是对照组。）
- **建议修法（一句话）**：把正则首支改为前缀匹配 `^127\.`（或 `/^(127(\.\d+){3}|localhost|\[::1\]|0\.0\.0\.0)$/`），并在改后用「隧道 stop 状态 + 127.0.0.1 打开」做一次回归。

### D2 · 外壳 `/favicon.ico` 404 —— **低**

- **现象**：每次打开外壳（公网与本地皆然）控制台一条 `404 /favicon.ico` 红错。
- **证据**：`p1-result.json`、`p3b-result.json` 的 logs；curl 实测 404。
- **建议修法**：在 `shell/index.html` `<head>` 加一行 `<link rel="icon" href="data:,">`（或放一个真 favicon，并可顺带用上品牌 logo）。

### D3 · 公网外壳每次加载都额外请求 `http://<公网IP>:8800/api/brand`，必失败并刷红 —— **低**

- **现象**：公网页面加载时，`ui-kit.js` 的「品牌兜底源」直连网关端口 8800（`http://39.96.200.45:8800/api/brand`）→ CORS/`ERR_FAILED`（或经 nginx 502），控制台一行红错 + 一条失败请求；同页已有同源 `/api/brand` 正常兜底，功能不受影响。
- **证据**：`p1-result.json` logs（CORS 与 `net::ERR_FAILED`）、`p0b-requests.json`（`req :8800/api/brand` 无响应）、curl 8800 → 502。
- **疑似根因**：`shared/ui-kit/ui-kit.js` `CP.brandSources()` 无条件追加「网关 `:8800/api/brand`」为第二来源；公网宿主下该端口并未被反代。
- **建议修法**：兜底源只在「同源取不到 brand 且 host 为 loopback」时尝试，或让公网 nginx 也给 `/api/brand` 一条非 CORS 依赖的路径（如把兜底改成同源 `/api/brand`）。

### D4 · 未知路由静默回落首页、无任何提示（且 hash 留在原值） —— **低**（判为「部分」）

- **现象**：`#/workspace/unknown-xyz`、`#/garbage` 均静默回到作品集首页，地址栏 hash 仍是被访问的错误值；访客不知道发生了什么。
- **证据**：`12-unknownroute-public.png`、`19-unknownroute-inapp.png`、`p2-result.json`。
- **建议修法**：`router()` 的 `showHome()` 分支里加一句轻提示（本地小 toast/横幅：「未找到该路线，已回到作品集首页」）并 `history.replaceState("#/")`。

### D5 · 说明：作者通道拒绝演示口令是**正确行为**（不是缺陷，防误报）

- 用公开演示口令 `owner123` 访问「作者通道」会得到 **401「owner 口令错误」**（品牌/材料面板各测一次）。核对 `shell/serve.py`（第 119–160、587–629 行）确认：写全站默认只认 `/api/auth/owner-login` 签发、`sub==__owner__` 的私密令牌，且演示 `owner` 账号（角色 owner）也会被显式挡下——**这是有意的安全设计**（根因注释写明曾因公开账号可改全站品牌而收权）。测试时我用本机 `_runtime/owner_password.txt` 的真实口令完成了作者通道正路径验证。

### D6 · 公网侧（部署/模块）三类脆弱点（疑似，均非外壳代码） —— **中/低**

- **D6a 链接抖动（环境）**：09:40 全通 → 09:45–09:52 全部入口 502（含外壳与 PDF）→ 10:02 恢复 → 10:12 又见部分模块 000/超时。平台侧 AGENTS.md 与 `docs/assets/github/online-demo.md` 记录了同一现象；建议演示前用 `tunnel_remote.py start` 自校验并盯着状态。
- **D6b 根绝对重定向（模块侧）**：P02 `/p02/`→`307 /login`、P04 `/p04/`→`307 /console.html`、P05 `/p05/`→`302 /login?next=/`。这些跳转是**根路径**，在公网 `/pXX/` 前缀下是否可用完全取决于 nginx 是否恰好把 `/login`、`/console.html` 路由到正确应用——10:09 实测恰好可渲染（`61`/`62` 截图），10:11:53 复测 `/login` 已回落为**外壳网关的 404**。建议：模块跳转带前缀（读 `X-Forwarded-Prefix`）或在 nginx 的 `/pXX/` 反代加 `proxy_redirect ~^/(.*)$ /pXX/$1;`。
- **D6c 公网 P05 挂载未完成（现象）**：三度尝试（09:37、10:04、10:10）P05 在公网 iframe 7–30s 内**零响应/未导航**，而本地 100% 正常、公网直连 curl 302 正常——疑似 p05 路由在抖动窗口内挂住；建议复测确认后再归因。

### D7 · 信息类（不建议改，仅记录）

- P02/P05 在 iframe 内显示**自己的登录页**而不是被外壳代登——符合 ADR-0003（P02 保留自身 Cookie RBAC 的有意例外）；公网 07:07 起 nginx 曾把 `/_next/*` 也路由到位，说明部署在向「子路径可用」方向演进。
- 状态条 `服务探活` 首次渲染显示「检测中」，6s 轮询后变 `10/10`——设计如此。
- `http://39.96.200.45:8090/`（不带模块路径）返回的是**外壳首页**（97,550B），不是模块导航页；功能无害，但作为「模块端口根」略反直觉。
