## 1. 项目目标与背景

这是一个面向**电商运营日常**的 AI 助手后端项目，用 Python + FastAPI + LangGraph 搭建。它把"数据 → 模型生成 → 媒体任务 → 多 Agent 审批 → 系统交付"串成一条可验收的链路，围绕六类高频运营动作：

| 能力 | 说明 |
|---|---|
| 商品诊断 | 把商品资料变成结构化诊断结论 |
| 竞品分析 | 竞品资料、监控、快照对比 |
| 创意策划 | 主图方案 / 视频脚本 / 标题 / 详情页方案 |
| 图片 / 视频生成 | 接入供应商做主图与视频素材生成，并可靠落库 |
| 库存建议 | 基于库存与销量给补货/清仓建议（LLM 或规则兜底） |
| 经营复盘 | 经营数据导入、复盘报告、广告实验与推荐 |

工程上的硬指标：**结构化 JSON 输出、模型只经受控工具网关访问数据、人工审批 + 断点恢复、Celery 异步、自动化测试、Docker 交付**。前端是课程提供的现成 Next.js 工作台，用于联调与展示，**不重写前端**。

**最终验收链路**：登录 → 创建商品/竞品资料 → 配置文本模型 → 生成诊断与创意 → 提交媒体任务 → 查询素材 → 创建 Agent Task → 人工审批与恢复 → 查看业务结果 → Docker Compose 交付与回归测试。

## 2. 技术栈

| 层 | 选型 |
|---|---|
| Web 框架 | FastAPI（路由统一 `/api/v1` 前缀，Swagger 在 `/docs`） |
| ORM / 迁移 | SQLAlchemy 2.x + Alembic（23 个迁移版本） |
| 校验 / 序列化 | Pydantic v2（`schemas.py`） |
| 异步任务 | Celery + Redis（`TASK_QUEUE_BACKEND=inline` 时本进程内同步执行，免 Redis） |
| 多 Agent 编排 | LangGraph，`langgraph-checkpoint-postgres`（生产）/ `InMemorySaver`（测试） |
| 可观测性 | OpenTelemetry（OTLP，端点为空时自动关闭） |
| 业务数据库 | **MySQL**（生产）/ **SQLite**（本地开发、自动化测试，模型已兼容通用 `JSON` 类型） |
| Agent 检查点库 | **PostgreSQL**（生产，独立端口 5433） |
| 模型供应商 | 文本：OpenAI 兼容（如 DeepSeek）；图片/视频：DashScope / 火山引擎等。均含"未配置即报错 / 规则兜底"的本地替身逻辑 |
| 前端工作台 | Next.js（TypeScript，现成，不重写） |
| 部署 | Docker Compose：API + Web + Worker + MySQL + Redis + PostgreSQL + （可选 Nginx） |

## 3. 功能模块

### 3.1 业务系统（基础闭环，验收入口统一用 Swagger）

- **认证与权限**（`auth.py` / `users.py` / `workspaces.py` + `services/auth|users|workspaces`）
  JWT 登录、RBAC（owner / operator / viewer）、Workspace 多租户隔离、用户管理。
- **店铺与平台账号**（`stores.py` + `services/...`）：店铺、平台账号、授权登记（oauth2 / official_api / service_provider / manual_export，明确拒绝绕登录/验证码/风控的采集方式）。
- **商品与 SKU**（`products.py` + `services/product_import|sku_inventory_import`）：商品资料、SKU、平台映射、批量导入。
- **库存**（`stores` 库存相关端点 + `services/inventory|inventory_advice|sku_inventory_import`）：库存、出入库流水、库存建议（LLM 或规则兜底）。
- **竞品**（`services/competitor_monitoring|competitor_monitor_scheduler`）：竞品、监控任务、快照、定时调度。
- **经营资料**（`services/performance_import|review`）：经营数据导入、复盘报告。
- **推广链接**（`promotion_links.py` + `services/promotion_links|public_link_parse_tasks|link_extraction`）：推广链接、点击追踪、公开链接解析任务。
- **投放**（`services/ad_experiments|ad_experiment_stats|ad_recommendations`）：广告实验、统计、推荐与人工确认。
- **模型设置**（`model_settings.py` + `services/model_settings`）：文本/图片/视频供应商运行时配置。

### 3.2 AI 智能素材（接入大模型）

- **诊断** `services/diagnosis`：商品结构化诊断。
- **创意** `services/creative_plans`：主图/视频脚本/标题/详情方案。
- **图片生成** `services/image_generation` + `generation_jobs`：提交、轮询（interval/attempts）、素材落库。
- **视频生成** `services/video_generation` + `services/volcengine`：提示词/工作流组装、签名鉴权、提交、轮询。
- **素材库与复核** `services/generated_assets`：生成资产管理与人工复核字段。

### 3.3 多 Agent 编排（受控工具 + 人工审批 + 断点恢复）

- **状态合同 / 策略** `agents/contracts.py` `agents/policy.py`：定义 Agent 状态结构、工具白名单、脱敏规则。
- **工作流图** `agents/graph.py`（商品操作图）+ `agents/platform_graph.py`（平台工作流图）：节点注册、条件路由、人工 `interrupt`、checkpoint。
- **专家 / 评估 / 注册 / 宿主** `agents/specialists.py` `evaluation.py` `registry.py` `harness.py`。
- **检查点持久化** `agents/persistence.py`：`PostgresSaver`（生产）/ 测试用 `InMemorySaver`。
- **可靠执行** `services/agent_tasks|agent_runs|agent_workflows|agent_leases|agent_maintenance` + `services/outbox`：Task / Run / Outbox / 审批 / 租约 / 维护。

## 6. 模块衔接方式（重点）

### 6.1 一次请求的生命周期

```
客户端
  │  Authorization: Bearer <JWT>, X-Workspace-ID: <可选>
  ▼
CORS 中间件
  ▼
路由依赖（auth.py 内集中）
  ├─ get_current_user       解析 JWT → User（每次重新校验账号可用性）
  ├─ resolve_workspace_access  解析租户（成员关系决定，绝不信任请求体里的租户 ID）
  └─ require_*_permission    RBAC：owner/operator/viewer；全局 owner 另管用户
  ▼
服务层（事务 + 领域规则）
  ▼
ORM（get_db 会话，请求结束自动关闭）
  ▼
DB
```

> **衔接关键**：鉴权、租户隔离、权限全部在**依赖层**收口，路由与服务不直接信任请求体里的 `workspace_id`，从根本上防越权。

### 6.2 Agent 工作流：受控工具 + 人工审批 + 断点恢复

```
创建 AgentTask
   │  services/agent_tasks
   ▼
Worker 拉起 LangGraph 图
   │  celery: agent.run_product_operation / run_registered_workflow
   ▼
节点: draft ──► 安全/风险检查 ──► interrupt(持久化到 checkpoint)
                                          │  等待人工审批
                                          ▼  同一 thread_id 恢复
                                  只持久化「被批准」的结构化产物
```

- **模型不能直接读写数据库**：所有数据访问必须经由 `agents/tool_gateway.py`（受控工具白名单 + 脱敏规则）。
- **检查点**：生产用 `PostgresSaver`（`persistence.py`），测试/本地用 `InMemorySaver`（见 `test_agent_*`）。
- **评估/策略**：`evaluation.py` 给草稿打分，`policy.py` 定义白名单与脱敏，`contracts.py` 约束状态结构。

### 6.3 异步媒体任务与可靠执行

- **图片/视频生成**：接口创建 `GenerationJob` → 任务队列（`inline` 本进程 / `Celery` 异步）→ 供应商提交 → 轮询（`IMAGE_POLL_*` / `VIDEO_POLL_*`）→ 素材落库（`generated_assets`）。
- **Outbox**：Agent 运行产生的外部副作用经 `services/outbox` + beat 调度（`dispatch-agent-outbox`）可靠投递；DB 状态幂等 + `agent_leases` 租约 fencing 吸收重复消息。
- **维护**：`agent_runtime` 维护运行健康，beat 每 30s 调度一次。

### 6.4 权限与多租户

- RBAC：`owner` / `operator` / `viewer`；`viewer` 仅有查看权限，全局 `owner` 另负责用户管理。
- Workspace：`WorkspaceMembership` 决定 `effective_role`；`X-Workspace-ID` 头选择目标工作区，缺省取成员默认工作区。

## 7. 配置说明（`.env` 关键项）

| 分类 | 变量 | 说明 |
|---|---|---|
| 数据库 | `DATABASE_URL` | 业务库。**必填**。生产 `mysql+pymysql://...`，本地 `sqlite:///./local_dev.db` |
| 队列 | `TASK_QUEUE_BACKEND` | `celery`（默认，需 Redis）或 `inline`（本进程，免 Redis） |
| | `REDIS_URL` | Celery broker/backend |
| Celery 队列 | `CELERY_TASK_DEFAULT_QUEUE` 等 | generation / agent / agent.workflow / maintenance |
| Agent 检查点 | `AGENT_CHECKPOINT_DATABASE_URL` 或 `AGENT_CHECKPOINT_HOST/PORT/USER/PASSWORD/DATABASE` | 生产用 PostgreSQL（端口 5433） |
| 鉴权 | `AUTH_SECRET_KEY` | 生产需 ≥32 位随机串 |
| | `AUTH_TOKEN_EXPIRE_MINUTES` | token 有效期，默认 10080（7 天） |
| 文本模型 | `LLM_BASE_URL` `LLM_API_KEY` `LLM_MODEL` | OpenAI 兼容；**三者都填才视为"已配置"** |
| 图片 | `IMAGE_PROVIDER` `IMAGE_BASE_URL` `IMAGE_API_KEY` `IMAGE_MODEL` `IMAGE_SIZE` `IMAGE_POLL_*` | 如 dashscope / 火山 |
| 视频 | `VIDEO_PROVIDER` `VIDEO_BASE_URL` `VIDEO_API_KEY` `VIDEO_MODEL` `VIDEO_SIZE` `VIDEO_DURATION` `VIDEO_POLL_*` | 如 dashscope / 火山 |
| 可观测 | `OTEL_EXPORTER_OTLP_ENDPOINT` | 为空则自动关闭 |
| 跨域 | `API_CORS_ORIGINS` | 前端地址，逗号分隔，已做尾部斜杠归一化 |

> 现有 `api/.env` 指向 MySQL 且 `LLM_API_KEY=<你的api-key>`（中文占位符）。**请勿直接把带中文占位符的 key 当真实配置**——它会让 `is_llm_configured()` 误判为"已配置"，进而在尝试请求时因中文报头触发编码错误（见 §9）。本地开发请用 `api/.env.sqlite`。

### 8.2 本地开发模式（已验证 · 免 MySQL/Redis/PostgreSQL）

这是**最快跑起来**的方式，不依赖任何外部服务：

```bash
cd api
# 方式 A：用本地模板覆盖配置（SQLite + inline）
cp .env.sqlite .env

# 初始化首个管理员账号
set BOOTSTRAP_EMAIL=owner@local.dev
set BOOTSTRAP_PASSWORD=LocalDev123!
venv/Scripts/python scripts/bootstrap_user.py

# 启动（自动用 SQLite + inline，建表在首次请求时由脚本/应用完成）
venv/Scripts/python scripts/run_local_dev.py
# 打开 http://127.0.0.1:8000/docs
```

> `scripts/run_local_dev.py` 会在进程内注入 `DATABASE_URL=sqlite`、`TASK_QUEUE_BACKEND=inline` 并启动 uvicorn；
> `scripts/bootstrap_user.py` 用环境变量创建首个 owner（密码只来自环境变量/命令行，不写代码）。

**本地自检（无需启动服务）**

```bash
venv/Scripts/python scripts/smoke_local.py
```
覆盖：建表 → 初始化管理员 → 登录 → 当前用户 → 店铺增查 → 模型设置 → 商品列表 → 401 拦截。

```bash

```
包含：API（8000）、Web（3000）、Worker（Celery + beat）、MySQL（业务库）、Redis（队列）、PostgreSQL（Agent 检查点）。

## 9. 测试与验收

- **自动化测试**：`pytest`（28 个测试文件，117 个用例）。在 **SQLite + 未配置 LLM** 的离线模式下 **117 passed**（6.6s）。
- **手工验收**：`http://127.0.0.1:8000/docs`，按 §1 验收链路逐步点选，接口文档内已标注输入示例与认证方式。

> **一个环境坑（与代码无关）**：现有 `api/.env` 里 `LLM_API_KEY=<你的api-key>` 是中文占位符。
> `is_llm_configured()` 只看"三个字段是否都非空"，占位符非空 → 被判定为"已配置" → 真去请求时中文 key 触发
> `httpx` 报头 `UnicodeEncodeError`。把 `LLM_*` 设为空即走"未配置/规则兜底"分支，测试全绿。
> 这解释了为什么用占位 `.env` 跑 `test_store_inventory_advice_uses_rule_fallback_for_low_stock` 会失败、而离线模式全过。
