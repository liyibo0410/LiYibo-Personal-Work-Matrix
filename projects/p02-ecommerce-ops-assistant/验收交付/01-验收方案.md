## 3. 判定标准

### 3.1 单条用例判定

| 结论 | 含义 |
|---|---|
| ✅ PASS | 实测结果满足期望，且留有可复核的实测证据 |
| ❌ FAIL | 实测不满足期望，或执行中抛出异常 |
| ➖ SKIP | 该链路不具备执行条件（如在线模式不直读对端库），已注明原因 |
| ⚠️ WARN | 结果可接受但需人工确认 |

### 3.2 整体通过准则

| 门槛 | 要求 |
|---|---|
| FAIL 数量 | **必须为 0**（任一 FAIL 即整体不通过） |
| 通过率 | PASS / (PASS + FAIL) **= 100%** |
| 回归测试 | `pytest` 全量用例 **0 failed / 0 error**，通过数 ≥ 50 |
| 脚本退出码 | **0**（1 = 存在 FAIL，2 = 脚本自身异常） |

> 判定不依赖人工印象：整体结论由脚本退出码给出，报告文件是可复现的书面证据。

## 4. 验收环境

### 链路 A · 离线验收（默认，主证据）

零外部依赖，任何一台装了项目 `venv` 的机器都能跑出确定结论。

| 项 | 配置 |
|---|---|
| 运行时 | Python 3.12.9（项目自带 `venv/`） |
| 数据库 | 临时 SQLite（`%TEMP%/ecommerce_acceptance.db`，每次重建） |
| 任务队列 | `TASK_QUEUE_BACKEND=inline`（免 Redis） |
| 模型密钥 | 显式置空 → 走"未配置 / 规则兜底"分支，保证可重复 |
| Agent 检查点 | `InMemorySaver`（进程内，不依赖 PostgreSQL） |
| 外部网络 | 不需要 |

### 链路 B · 在线验收（现场演示辅证）

| 项 | 配置 |
|---|---|
| 后端 | 本地或容器运行中的 `http://127.0.0.1:8000` |
| 数据库 | MySQL（业务库）+ PostgreSQL（Agent 检查点，端口 5433） |
| 队列 | `TASK_QUEUE_BACKEND=celery` + Redis + Worker |
| 模型密钥 | 已配置真实供应商（文本 OpenAI 兼容；图片/视频 DashScope 或火山） |

## 6. 验收执行

### 6.1 一键执行（推荐）

```bash
cd api
..\venv\Scripts\python.exe scripts/acceptance_check.py
```

可选参数：

| 参数 | 说明 |
|---|---|
| `--skip-pytest` | 跳过全量回归（快速复核业务链路时使用） |
| `--online http://127.0.0.1:8000` | 改为对运行中的后端做在线验收 |
| `--email` / `--password` | 在线模式登录账号（默认 `admin@local.dev` / `LocalDev123!`） |
| `--report-md` / `--report-json` | 自定义报告输出路径 |

### 6.2 前置条件核查

| 检查项 | 命令 | 期望 |
|---|---|---|
| 虚拟环境可执行 | `venv\Scripts\python.exe -V` | Python 3.12.x |
| pytest 可用 | `venv\Scripts\python.exe -m pytest --version` | 输出版本号 |
| 端口未被占用（在线模式） | `netstat -ano \| findstr :8000` | 仅一个后端实例 |

### 6.3 结果读取

脚本执行结束后：

1. 控制台打印 `验收结果：通过 / 不通过`、用例统计、通过率、以及每条 FAIL 的摘要；
2. 生成 `acceptance_report.md`（人读）与 `acceptance_report.json`（可接入 CI 门禁）；
3. 退出码 `0` 表示整体通过。

## 7. 通过准则与不通过处理

| 情形 | 处理 |
|---|---|
| 全部 PASS，FAIL=0 | 判定**通过**，报告归档，进入签署 |
| 出现 FAIL | 判定**不通过**；按 `acceptance_report.md` 的「未通过项明细」定位 → 修复 → 重跑脚本，直至 FAIL=0 |
| 出现 SKIP | 记录原因；若系链路 B 专属项，须在在线验收中补齐 |
| 脚本退出码 2 | 属脚本自身异常（非业务缺陷），须先修脚本环境再重跑 |
| 结果不可复现 | 以离线链路 A 为准（密钥、外部服务、进程状态均被隔离，可重复） |

## 9. 已知限制与风险（如实说明）

| 项 | 说明 | 影响 |
|---|---|---|
| 在线链路依赖商业密钥 | 真实出图/出片需供应商密钥与配额，离线链路用"未配置即报错 / 规则兜底"验证分支正确性 | 素材**质量**需在线验收补充，功能**链路**已被离线覆盖 |
| inline 模式无后台调度 | `TASK_QUEUE_BACKEND=inline` 时无周期调度器，失败任务不会自动重排 | 离线验收用"提交 + 取消"证明任务落库与状态机；自动重排需 Celery 链路 |
| Agent 审批的端到端异步 | Outbox 派发经 Celery，离线无 Broker | 审批与恢复能力改用**项目真实 LangGraph 图**直接验证（AGT-11 ~ AGT-14），证据等价且更强 |
| 前端未纳入自动化验收 | 前端为现成工作台，本次不重写 | UI 需按 §6 步骤人工目视确认 |

> 上述限制均为**已知且已在验收项中显式声明**，不构成隐藏风险。
