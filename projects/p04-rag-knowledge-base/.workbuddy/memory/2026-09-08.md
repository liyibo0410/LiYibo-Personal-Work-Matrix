## RAG 批量评估 (eval/eval.py) 跑通

**触发场景**：跑 `eval/eval.py` 评估 3 条 HAK180 烫金机问题，连续撞三个坑。

### 坑 1：Milvus "Proxy is not ready yet"（08:41:56 首次）
- `docker-compose ps` 显示 milvus-standalone 已 healthy，但 `MilvusClient.__internal_register` 在 10 秒超时内仍报"Proxy is not ready yet"
- **根因**：gRPC Proxy 端口 19530 的 ready 状态滞后于 healthcheck（9091/healthz）。容器启动约 3 分钟时评估程序正好撞上去。
- **绕路**：直接重跑。等几分钟容器完全 ready 后就过了。
- **改进候选**（未做）：`utils/milvus_utils.py:get_milvus_client()` 加连接重试 + 健康校验（当前是裸单例，无任何重试）。

### 坑 2：node_web_search_mcp.py 5 秒 initialize 超时
- 报错 `mcp.shared.exceptions.McpError: Timed out while waiting for response to ClientRequest. Waited 5.0 seconds`
- 端点配置**正确**（`MCP_DASHSCOPE_BASE_URL=.../mcps/WebSearch/mcp`，不是过时的 `/sse`）
- 独立 probe 用真实 key 测 `MCPServerStreamableHttp`：timeout=5/10/15/20/30 全部 0.2 秒成功，connect → list_tools → call_tool 全程 OK
- **根因不确定**：可能是 LangGraph 并发执行多路搜索 + `asyncio.run()` 在 worker thread 里与 anyio/MCP SDK 的兼容性问题，握手阶段被掐断
- **修复**：在 `process()` 里给 `asyncio.run(self._mcp_call(query))` 加 try/except，MCP 失败时记录 warning 并返回空 results，让 RAG 退化为只走两路向量检索
- **设计意图**：联网搜索是"锦上添花"而非主链路，节点失败不应拖死整个图

### 坑 3：node_rerank.py 兜底分支 bug + 网络代理 502
- **网络抖动**：dashscope.aliyuncs.com:443 经本机代理出现 502 Bad Gateway，`requests.exceptions.ProxyError`，导致 `rerank_documents` 抛错进入 except 分支
- **Bug**：except 分支写成了 `return [{**merged_multi_docs, "score": None}]` —— `merged_multi_docs` 是 `list[dict]`，** 不能展开，触发 `TypeError: 'list' object is not a mapping`
- **修复**：改为 `return [{**doc, "score": None} for doc in merged_multi_docs]`，跟 try 块里的列表推导式保持一致，兜底保持 `list[dict]` 结构

### 评估结果（eval/qa_result.csv）

观察：
- Context Recall 全 1.0 → 检索召回完整，所有 GT 都能在 reranked_docs 里找到
