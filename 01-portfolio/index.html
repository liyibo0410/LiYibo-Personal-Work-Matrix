一条数据闭环，六个工程决策

闭环的意义是口径只有一份：同一个「GMV」在数据中台、运营看板、销售考核里算的是同一个数； 低分会话回流微调层，新模型再回到 P01 / P02 的回复里。下面六条 ADR 是这套合并形态里我认为最该被追问的决策， 每条都连同代价一起写 —— 收益谁都会讲。

P06 数据中台→ P04 知识库 / P07 素材→ P01 客服 / P02 运营→ P09 销售考核→ P10 微调↺ 新模型回到 P01 / P02
入口 · ADR-0001

微前端外壳 + iframe 挂载，不做单体合并。三类前端栈异构（Next.js / Vue 3 + Vite / FastAPI 直挂静态页），合并等于重写四个前端；代价是主题与令牌只能运行时尽力同步。

认证 · ADR-0003

外壳用 shared/auth 签发 HS256、postMessage 下发，模块只校验不重造登录。P02 保留自身 Cookie RBAC —— 改它会绕过它已有的权限模型，这是有意识的例外。

端口 · ADR-0002

SERVICE_REGISTRY 是端口唯一真源，跨模块调用禁止硬编码对方端口。起因是一次真实故障：P03 前端把后端写成 8000，实为 8030，平台内直接不可用。

取数 · ADR-0004

P02→P06、P07→P06、P09→P01 真实 HTTP。降级态用「少返回」而不是「编一个」：degraded=True 且响应里直接不含 metrics 字段。

视觉 · ADR-0005

ui-kit 令牌单一真源：静态模块运行时挂 /shared，构建型模块构建期内联 + 主题桥；代价是改色后必须重新构建。本页与在线系统用的是同一套令牌。

例外 · ADR-0006

P05 只用标准库：客户机 python run.py 即跑，不必先装 Docker。风险打分要的是确定性与可复现，这一点比「栈统一」更重要。

真实 / 模拟边界

交付里最容易翻车的不是功能少，是「演示能跑、上线不跑」。所以每个模块我先把线划死： 哪条链路是真的、哪里是模拟、以及为什么在这一处主动选模拟。同样的话在系统 UI 标注、接口字段与 _evidence/ 里都能对上（如 P08 的 /health 自陈 mock_boundaries、P10 的 endpoint_url: null）—— 双处标注是硬规则，不是我挑给面试官看的话术。
