## 二、🔑 这解决了 P04 的关键难题

### 问题回顾

Token Plan（`sk-sp-`）端点上**没有 embedding / rerank 模型** —— 而 P04 RAG 必须用这两个能力。

### 解法：全走本地

| 能力 | 来源 | 原因 |
|---|---|---|
| Embedding | **本地 `BAAI/bge-m3`** | 模型已有，零下载 |
| Rerank | **本地 `BAAI/bge-reranker-large`** | 模型已有，零下载 |
| LLM 生成 | **Token Plan（`sk-sp-`）** | 先用着，够用 |

**收益**：
- ✅ 省掉约 **6.5GB 模型下载**
- ✅ 不依赖 Token Plan 的缺失能力
- ✅ 不碰 Coding Plan 的条款灰区（那套餐限 "Coding tools only"）
- ✅ **面试加分**：可以说"向量化与重排全部本地私有化部署，数据不出内网"

**唯一需要补的**：`torch`（CUDA 版，约 3-4GB）。这是 BGE 系列的运行时依赖，绕不开。

> 备选：如果连 torch 都不想装，可以用 **Ollama 跑 `bge-m3`**（`ollama pull bge-m3`，约 1.2GB，走 HTTP API，零 torch）。
> 但 rerank 仍需 torch（Ollama 不支持 cross-encoder reranker）。**所以最终还是要装 torch，建议直接走本地 BGE 全套。**

## 三、代码里怎么用

```python
# ---- Embedding（稠密 + 稀疏）----
from FlagEmbedding import BGEM3FlagModel

# 完整副本（2026-10-12 核查修正：原先记的 modelscope_cache 路径只有 48M，是残缺副本）
EMBED_PATH = r"D:\software\ai_models\BAAI\bge-m3"
embedder = BGEM3FlagModel(EMBED_PATH, use_fp16=True)
out = embedder.encode(
    ["文本1", "文本2"],
    return_dense=True,
    return_sparse=True,   # 稀疏向量用于 BM25 式关键词匹配
)
dense_vecs  = out["dense_vecs"]
sparse_vecs = out["lexical_weights"]

# ---- Rerank ----
from FlagEmbedding import FlagReranker

RERANK_PATH = r"D:\ai_models\models\BAAI--bge-reranker-large\snapshots\master"
reranker = FlagReranker(RERANK_PATH, use_fp16=True)
scores = reranker.compute_score([["用户问题", "候选文档片段"]])
```

**显存占用**（RTX 4060 8GB，fp16）：
- BGE-M3 推理 ≈ 1.5-2GB
- bge-reranker-large 推理 ≈ 1.5GB
- 两者**不要同时常驻**会到 3.5GB，可以接受；如需更省可用 CPU 跑 rerank
