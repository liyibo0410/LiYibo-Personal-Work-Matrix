## 任务 1 · 广告法合规词与极限词检测 ★核心卖点

```
【任务】
给商品文案生成能力加「广告法合规词与极限词检测」，输出三态判定（block / review / pass）。

【背景】
电商运营用 AI 生成商品文案，需自动检测是否违反《广告法》第九条等绝对化用语禁令。
这是本项目的核心卖点，面试时要能演示"给一段含违规词的文案，被识别并拦截"。

【接入点】（已勘察确认，直接用）

1. 新建检测模块：api/app/services/compliance.py
   - 词库从 JSON 文件加载，不要硬编码词条
   - 词库文件已由 P1 准备好：api/app/resources/compliance_lexicon.json
   - 评测集已由 P1 准备好：api/evals/compliance_cases.jsonl

2. 插入点（必须在这两处，理由见下）：
   - api/app/services/creative_plans.py:80-88（generate_llm_main_image_plans 组装 payload 的循环内）
     覆盖 主图 title / headline / sub_headline / proof_points
   - api/app/services/creative_plans.py:268-274（generate_llm_video_script_plans 组装循环内）
     覆盖 视频 hook / voiceover / cta

   ⚠️ 为什么必须在 service 层而不是 API 路由层：
   api/app/agents/tool_gateway.py:219-220 会直接调用 generate_main_image_plans /
   generate_video_script_plans，**绕过 HTTP 路由**。若检测放在路由层，Agent 产生的文案会漏检。
   service 层是 HTTP 与 Agent 两条链路的唯一公共收口点。

3. 兜底：creative_plans.py:51-62 的 generate_main_image_plans 在 except 分支里有多个 return 出口，
   规则兜底路径（generate_rule_based_main_image_plans，:138）也要覆盖。
   若重构为单一出口风险大，就在 :51 入口函数末尾对本层 plans 再校验一次。

【必须满足】
1. 词库 JSON 化，可维护（运营改词不发版）；字段含 id/category/risk/surface/match_type/
   boundary/exceptions/suggestions
2. 三级匹配：精确词 → 容错正则（对抗插符号/形近字/全角空格/零宽字符）→ 上下文升权
   · "第一" 右侧跟 次/时间/批/个/天/年 → 判定为序数，**不算违规**
   · "第一" 左侧出现 全国/行业/销量/全球 → **升为高风险**
   · "全国包邮" / "最高温度" / "唯一序列号" → 白名单，不算违规
3. 输出：命中词 + span 区间 + 风险等级 + 建议替换词 + 法条依据
4. 结果写入 CreativePlan.content 的 JSON 中（如 payload["compliance"]），**不改表结构**
5. 通过 api/app/api/routes/products.py 的两个生成接口可被前端读到：
   · POST /api/v1/products/{product_id}/creative-plans/main-images/generate （:892）
   · POST /api/v1/products/{product_id}/creative-plans/video-scripts/generate （:937）
6. 写单元测试（api/tests/test_compliance.py），覆盖：正例 / 负例 / 对抗例 / 边界例
7. 用 api/evals/compliance_cases.jsonl 跑评测，输出拦截率（召回）与误报率（精确率）

   ⚠️ 数据说明书（P1 已校验，词库 106 条规则 / 评测集 36 条用例）：
   · 词库：6 大类（absolute 23 / promise 21 / medical 21 / authority 18 / timing 17 / finance 6），
     风险分布 high 74 + medium 32；白名单 25 短语 + 3 正则；变体映射 8 条；零宽字符 5 个
   · 评测集 verdict 分布：block 18 / pass 10 / review 8；
     difficulty 分布：easy 14 / medium 4 / hard 4 / adversarial 8 / boundary 6
   · **对抗例（difficulty=adversarial）的 gold.labels 写的是「归一化后的规范词」**，
     例如 TC-0023 原文是「最\u200b好用的面膜，全网\u3000最低价」，而 label 写「最好」「全网最低价」。
     这是**有意设计**——正确实现在归一化后应能匹配上；若匹配不上，说明归一化层没做对，
     不要改 eval 数据去迁就实现。
   · 判定门槛建议：高危召回 ≥ 98%、整体误报率 ≤ 5%、变体绕过率 < 5%

【禁止】
- 不要改 CreativePlan 的数据表结构
- 不要动 api/app/services/llm.py（那是任务 4 的范围）
- 不要删除 creative_plans.py 里现有的规则兜底实现
- 不要修改任何 .env / .env.sqlite

【验收】
给定文案「这款面膜能快速消炎杀菌，全国销量第一，仅此一次！」
→ verdict = block，命中 消炎 / 杀菌 / 第一 / 仅此一次，span 定位准确，有替换建议
给定文案「全国包邮，最高支持 120W 快充，第一次使用建议先测试」
→ verdict = pass，零误报
```
