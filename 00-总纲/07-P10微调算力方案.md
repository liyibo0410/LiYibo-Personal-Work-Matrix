# P10 · 模型微调算力方案

> 前提：本机 **RTX 4060 Laptop 8GB**；算力云账户余额 **¥9.5**。
> 目标：用最小成本，交付一份**有真实训练证据**的微调成果。

---

## 一、结论先行

| 结论 | 说明 |
|---|---|
| **本机是主力** | 开发、调试、数据准备、跑通全流程，**全部在本地做，0 成本** |
| **云 GPU 只跑一次** | 只在"最终演示训练"时开机，¥9.5 够用且有富余 |
| **绝不在云上开发** | 环境安装、调试报错都在计费。这是最容易烧钱的地方 |
| **训练 ≠ 烧钱，准备才烧钱** | 真正训练几分钟，装环境+调错可能要 1-2 小时 |

## 二、本机（RTX 4060 8GB）能做什么

| 模型规模 | 方式 | 显存占用 | 可行性 |
|---|---|---|---|
| Qwen2.5-0.5B | LoRA (fp16) | ~3GB | ✅ 很舒服 |
| Qwen2.5-0.5B | 全参微调 | ~6GB | ✅ 可以 |
| **Qwen2.5-1.8B** | **LoRA (fp16)** | **~5-6GB** | ✅ **推荐主力配置** |
| Qwen2.5-1.8B | QLoRA (4bit) | ~3GB | ✅ 舒适，可加大 batch |
| Qwen2.5-7B | QLoRA (4bit) | ~6-7GB | ⚠️ 勉强：必须 gradient checkpointing + batch=1 |
| Qwen2.5-7B | LoRA (fp16) | ~16GB | ❌ 跑不了 |

**判定**：本机可独立完成到 **1.8B LoRA**；7B 需要云 GPU。

> 注意：**8GB 还要分给系统/浏览器**。实际可用约 7.5GB，上面数字留了余量。

## 三、¥9.5 在云上能买到什么

### 主流算力云单价参考（按量计费，实际以平台为准）

| GPU | 显存 | 参考单价 | ¥9.5 可租 |
|---|---|---|---|

| RTX 4090 | 24GB | ¥1.8-2.8/h | **3.5-5 小时** |

### 能完成的任务（以 4090 计）

| 任务 | 预计耗时 | ¥9.5 够几次 |
|---|---|---|
| 0.5B LoRA · 500 条 · 3 epoch | 3-8 分钟 | 很多次 |
| 1.8B LoRA · 500 条 · 3 epoch | 10-20 分钟 | 十几次 |
| **7B QLoRA · 500 条 · 3 epoch** | **30-60 分钟** | **✅ 够跑 1 次完整 + 评测** |
| 7B QLoRA + 完整评测 + 试错 | 1.5-2 小时 | ✅ 够，但没浪费空间 |

**结论：¥9.5 足够在云上跑一次完整的 7B QLoRA 训练 + 评测。**

### ⚠️ 但真正的成本陷阱在这里

| 环节 | 耗时（也在烧钱） |
|---|---|
| 拉镜像 / 装 torch+cuda+peft | 20-40 分钟 |
| 数据上传与环境验证 | 10-20 分钟 |
| 调试报错（第一次跑几乎必然踩） | 30 分钟 - 2 小时 |
| 模型下载回本地 | 5-15 分钟 |

**如果没有提前准备，¥9.5 可能全耗在"装环境 + 调错"上，一次训练都跑不完。**

> **📌 更新（2026-10-12）：使用者确认"钱不是约束，可以充值"。**
> 那么建议直接租 **RTX 4090 24G**（约 ¥2-2.8/h），理由：
> - 可以跑 **7B 全参 LoRA**（而非被迫用 QLoRA），训练更稳定、效果更好
> - 显存充裕可以开更大 batch，训练更快
> - 2 小时开销约 **5-12 元**，成本可以忽略
>
> 但**策略不变**：仍然是"本地开发调试 → 云上只跑一次正式训练 → 立刻下载产物关机"。
> 省钱不是目的，**不把开发时间烧在计费上**才是。

## 四、推荐执行策略：三段式

```
【阶段 1】本地 · 0 成本 · 占总工作量 80%
  ├─ 准备微调数据集（100-500 条，电商客服/合同审查话术）
  ├─ 写训练脚本（支持配置化：模型、LoRA rank、lr、epoch）
  ├─ 本地跑通 0.5B 与 1.8B 全流程（训练→评测→保存 adapter）
  ├─ 把报错全部踩完，形成"一键训练脚本"
  └─ 产出：requirements.txt + train.py + data.jsonl + eval.py
                    ↓ 打包上传
【阶段 2】云上 · 消耗 ¥9.5 · 只跑一次
  ├─ 开机 → 用平台预装 PyTorch 镜像 → 装依赖（一条命令）
  ├─ 直接跑 7B QLoRA 训练（脚本已调好，不需要再调试）
  ├─ 跑评测 → 截图 loss 曲线 + GPU 占用 + 成本页
  └─ 下载 LoRA adapter（几百 MB，不是全量模型）→ **立刻关机**
                    ↓
【阶段 3】本地 · 0 成本
  └─ 把 adapter 挂到 vLLM/Ollama，验证可调用，产出 curl 证据
```

**核心思想**：把云 GPU 当成"一次性计算资源"，而不是"开发环境"。

## 五、云上省钱清单（照着做）

- [ ] **提前本地写好** `requirements.txt` 与训练脚本，云上一条命令装完
- [ ] 选**平台预装镜像**（PyTorch 2.x + CUDA 12.x），省 20-40 分钟
- [ ] 数据提前打包好，用平台网盘/数据盘导入，别现场造
- [ ] 训练脚本设 `save_strategy="epoch"` + `save_total_limit=1`，只留最优
- [ ] 训完**只下载 LoRA adapter**（几十到几百 MB），不要下载整个基座模型
- [ ] 评测在云上一次跑完（本地重新跑要下载模型，更慢）
- [ ] **设个闹钟提醒关机** —— 按量计费，关机才停费
- [ ] 开机前先看一眼"当前计费单价"，心里有数

## 六、必须产出的证据（面试用）

| 证据 | 用途 |
|---|---|
| `loss` 曲线截图 | 证明真训练了，不是编的 |
| **GPU 占用截图**（nvidia-smi） | 证明真在卡上跑 |
| 微调前后评测对比表 | 证明有提升（**幅度小也照实写**） |
| **成本截图**（实际花了多少钱） | ⭐ 面试可讲"我用 9.5 元完成了一次 7B 微调实验"—— 这是**成本意识**，企业很吃这套 |
| LoRA adapter 调用成功截图 | 证明产物可用 |

> **诚实提醒**：小数据集 + 少 epoch 的 LoRA，效果提升可能很不明显。**照实写**。
> 面试官更在意你是否理解"为什么提升小"（数据量不足 / 任务太简单 / 基座已够强），而不是数字好看。

## 七、还有一个免费选项

如果 ¥9.5 想省着用：

- **Kaggle Notebooks**：每周约 30 小时免费 GPU（T4 16GB / P100）
- 优点：免费额度大，T4 16GB 显存比本机 8GB 大一倍，可跑 7B QLoRA
- 缺点：国内访问需要网络条件；环境每次重装；数据要上传到 Kaggle Dataset

**建议**：本机跑通 → Kaggle 免费额度跑 7B → ¥9.5 留作应急或再跑一次更好的版本。
