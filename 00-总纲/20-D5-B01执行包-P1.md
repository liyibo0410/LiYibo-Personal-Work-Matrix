### ① D5-01 断崖量纲失配

**不用读验收报告了**，关键事实如下：

| 位置 | 现状 |
|---|---|
| `processor/query_processor/nodes/node_rerank.py:20` | `RERANK_GAP_ABS: float = 0.5` |
| `processor/query_processor/nodes/node_rerank.py:22` | `RERANK_GAP_RATIO: float = 0.25` |
| `processor/query_processor/nodes/node_rerank.py:151` | `rel_gap = abs_gap / (abs(current_score) + 1e-6)` ← **病灶** |
| `utils/reranker_http_utils.py` `_rerank_local()` | 返回 BGE logits，**无归一化** |

**实测数据（P1 独立跑）**：

```
场景「6 条全部语义相关」→ 断崖只保留 3 条（= RERANK_MIN_TOPK 下限）
场景「真实 e2e 链路」   → 候选 5 条，保留 3 条：
    [2] +0.9482 保留
    [3] +0.6719 ✂ 砍掉   ← 正分=相关，只差 0.2763
    [4] +0.0752 ✂ 砍掉
触发原因: rel_gap = 0.2763/0.9482 = 0.2915 ≥ 0.25
         （abs_gap 0.2763 < 0.5，绝对阈值没触发 → 是 rel_gap 干的）
```

**两层根因**：
1. 阈值 0.5/0.25 是按**云端 0~1 分**调的；本地 BGE 输出 **logits（-9.48 ~ +5.05）**，跨度 15 倍
2. `rel_gap` 分母 `abs(current_score) + 1e-6`，**current_score 接近 0 时分母趋零 → 比值爆炸**。
   logits 的正负分界就在 0 附近，这是高频事件

**云端真实分数（今天实测，佐证量纲）**：`[0.9155, 0.6221, 0.0010]` —— 0~1，
正是断崖阈值设计时所基于的量纲。

**要求三条**：
1. `_rerank_local()` 返回前 **sigmoid 归一到 0~1**（原始 logits 留在内部变量供 debug）
2. `rel_gap` 分母改**全局分数跨度** `(max_score - min_score + ε)` 或加常数项 ——
   **这条即使做了 sigmoid 也要修**，是独立的数值 bug
3. 补集成测试（用真实 `NodeRerank._step_3_cliff_cutoff`，不是自己复写逻辑）：
   ```python
   def test_cliff_does_not_over_truncate_related_docs():
       """6 条全部语义相关 → 断崖后应保留 >= 4 条，不能砍到下限 3"""
   ```
