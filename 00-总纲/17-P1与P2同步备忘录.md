## 一、P1 是怎么验收的（Qoder 必须知道）

**P1 从不复用你的自检脚本。** 每轮复核都从**外部第三方视角**独立取证：

| 手段 | 说明 |
|---|---|
| 独立验证脚本 | 写在 `_evidence/<模块>/verify_*.py`，不 import 你的 selftest |
| 外部 HTTP 视角 | 起真实服务、发真实 HTTP 请求，断言**HTTP 状态码**而不只是函数返回值 |
| 端到端真实链路 | 关键功能必须**真跑一遍**（如 LLM 复核要真调模型，不能只测降级分支） |
| 回归对比 | 你的自检项数只增不减；P1 脚本的通过数不得下降 |
| 全树扫描 | 版本串、硬编码残留等做全目录 grep，不只看你改过的文件 |

**所以**：自检全绿 ≠ 验收通过。自检是**必要条件**，不是充分条件。

## 二、四轮交付缺陷类型学（请逐条对照自查）

| # | 缺陷模式 | 实例 | 根因 | 防范 |
|---|---|---|---|---|
| 1 | **批量替换破坏字符串定界符** | D3：`["核心卖点“, ”使用效果“]` 中文引号混入代码 | 全局替换命中字符串内部 | 替换后 grep 检查引号配对、跑语法检查 |
| 2 | **返回加工后数据而非原始数据** | D3：`matched_text` 返回归一化文本（去零宽/繁转简），前端用 span 切原文会失配 | 只验"能取到值"，没验"取到的是不是原文" | 凡有坐标/span 的地方，必须断言"按 span 切原文 == 返回值" |
| 3 | **只测降级路径，不测真实路径** | D4-02：新增 4 条自检全在"未配 Key"下断言，从未验证"配好 Key 能真用" | 真实路径要配凭据/网络，容易跳过 | **两条路径都要测**：降级要正确、正常要真生效 |
| 4 | **函数层测了、传输层没测** | D4-01：`auth.login()` 返回 False 被测到，但 HTTP 状态码仍是 200 | 断言的是函数返回值，不是 HTTP 响应 | 涉及 HTTP 的契约，断言**状态码**而不只是返回体 |
| 5 | **项目自带机制未被发现** | D4-01 修复时手工改 7 个文件，漏 29 处；项目本有 `rebrand` 幂等工具 | 只搜索自己要改的文件，没读项目约定文档 | 动手前先读 `app/__init__.py`、`tools/README.md`、项目 CHANGELOG 头部 |

> **共性**：这 5 类都不是"不会写代码"，而是**验证面不全 / 没读项目约定**。
> 规律很清楚——**"改对了"和"改全了"是两件事。**

## 三、硬性验收清单（P1 每轮必查，请自检后再交付）

```
□ 项目自检全绿，项数只增不减（如 P05 当前基线 66）
□ 新增能力的【降级路径】有自检（无配置/无网络/异常输入 都不能崩）
□ 新增能力的【正常路径】有自检（真跑一遍，拿真实结果，不是 mock）
□ 涉及 HTTP 的改动：断言【HTTP 状态码】而不只是响应体 code
□ 涉及坐标/span 的改动：断言【按坐标切原文 == 返回值】
□ 全局替换后：grep 检查字符串定界符未被破坏
□ 升版本：走项目自带收口工具（P05 是 tools/_onetime/rebrand_hengjian_v202.py），
  改前备份，改后全树 grep 旧版本串应为 0（__pycache__ 除外）
□ 全树扫描残留：不要只 grep 自己改过的文件
□ 交付说明里写明：改了哪些文件、新增/修改了哪些自检项、怎么复现验收
```
