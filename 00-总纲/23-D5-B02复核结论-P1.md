### 为什么变异 B 抓不到 —— 用真实数据解释（这是判定依据）

P1 探针 `probe_relgap_discriminator_p1.py` 实测：

```
分数(全精度): [0.98631052, 0.00007844, 0.00007662, 0.00007602, 0.00007602, 0.00007602]
span = 0.98623550
idx=2 cur=0.00007662 nxt=0.00007602 abs_gap=0.00000060
      rel_new = 0.000001       rel_old = 0.007681
```

**关键事实**：sigmoid 之后，不相关文档在 **FP16 精度下分数几乎完全相同**
（差异仅 6e-7）。此时 `rel_old` 仅 **0.0077**，远达不到 0.25 阈值。

→ **rel_gap 分母加固在当前真实数据下属于「防御性冗余」**：
它防的是「低分区 + 分数有细微差异」这一极端情形，FP16 量化后基本不出现。

**判定**：变异 B 抓不到 ≠ 测试失败。主缺陷（sigmoid）已被牢牢锁死；
加固项属中低风险覆盖缺口，**不阻断**，但必须显式标注（见修补项 1）。

### 🔴 修补项 1（非阻断）：一处恒真断言 + 文档数学错误

`tests/test_node_rerank_cliff.py::TestCliffEqualScoresBoundary::test_near_equal_scores_small_span`

- docstring 声称：`span=0.001` 时 `rel_gap ≈ 1.0` → 触发截断 → 砍到 MIN_TOPK
- **实测**：8 条分数 `0.8 - 0.001*i` → `span = 0.007`，`abs_gap = 0.001`，
  `rel = 0.001 / 0.0070001 = 0.1429 < 0.25` → **不触发** → 保留 8 条
- 断言写的是 `len(result) >= RERANK_MIN_TOPK`（即 ≥3），实际值 8 → **恒真**

这正是「测试存在但测不到缺陷」的形态：文档描述与代码行为不符，
且断言松到不可能失败。要求 P2 二选一：
**(a)** 修正 docstring 并把断言收紧到与真实行为一致（如 `== 8`）；
**(b)** 若确实想测「极小 span 触发截断」，则重新设计输入使 `rel_gap` 真能 ≥0.25
（例如 `score = 0.8 - 0.09*i`，使 `abs_gap/span ≈ 0.125`… 需实算验证后写死）。

> 附：该类还带 `@pytest.mark.needs_model`，但 `test_near_equal_scores_small_span`
> 未使用模型，标记冗余（会误导他人以为它依赖 GPU）。

1219.21s   src=5  degrade=''   Q: hak 180 烫金机：雷暴天气期间可以使用本设备吗？

这属于**缺陷类型学第 ④ 类（统计口径/下游量纲）**：
改一个统计口径 = 改掉所有下游结论。若拿当前报告去面试讲"云端快 3 倍"，
