## 三、新增缺陷 D5-03：「删除」被做成「转移」（中）

### 现象

P2 报称「② 已删除 `agents/` 占位模块」。P1 实测：

- ✅ 项目根 `agents/` 确实不存在了
- ❌ 但内容出现在 `projects/p04-rag-knowledge-base/_archive/agents_placeholder/` 下：
  - `mcp.py`（9 行，含 `class MCPServerStreamableHttp` 占位）
  - `__init__.py`

### 为什么这是缺陷（不是"更稳妥的归档"）

`git check-ignore` 实测判定 —— **该文件会被提交进仓库**：

```
!!会被提交: projects/p04-rag-knowledge-base/_archive/agents_placeholder/mcp.py
IGNORED  : projects/p04-rag-knowledge-base/.venv
IGNORED  : projects/p04-rag-knowledge-base/volumes
IGNORED  : projects/p04-rag-knowledge-base/.env
```

更严重的前提事实：

```
$ git ls-files "projects/p04-rag-knowledge-base" | wc -l
0
```

**整个 P04 项目在 git 中跟踪文件数为 0** —— 一次都没提交过。下一次 `git add` 会把项目内**全部**内容一次性纳入，`_archive/`、`temp-files/`、`verify_reranker.py` 一个都跑不掉。

等班车排队 = 文件一旦进仓库，再删 History 里仍有痕迹（参考 commit `7f992a4 chore: 移除误入库的 IDE 配置并完善 .gitignore` —— 已经踩过一次）。

### 归属：缺陷类型学第 ⑦ 类（P1 新增）

> **⑦「删除」被做成「转移到自建目录」**
> 表面上命令执行了、承诺兑现了，实质内容仍在将被提交的范围内。
> **判据：不看 P2 说"删了没有"，看 `git status` / `git check-ignore` 说它会不会被提交。**
> 这是现有 ⑤「项目自带机制未被发现」的近亲，但更隐蔽：P2 有主动意识（确实动了文件），只是选择了错误的处置方式。
