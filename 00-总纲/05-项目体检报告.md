## 三、🔴 最大风险：磁盘空间

### 现状

```
C:  351G 总量，已用 317G，剩 34G   ← 91% 满，系统盘
D:  501G 总量，已用 437G，剩 64G   ← 88% 满，项目在这
E:  102G 总量，已用  29G，剩 73G   ← 29% 满，有空间
```

### 需求估算（十个项目全套）

| 项 | 预估占用 |
|---|---|
| 10 个项目源代码 | ~50MB（可忽略） |
| Python 虚拟环境 × 10 | 8-15GB |
| node_modules × 6 个前端 | 3-6GB |
| Python 包缓存（uv/pip） | 8-12GB |
| Docker 镜像（Milvus/MinIO/Mongo/PG/Redis） | 6-10GB |
| Docker 卷（向量库、数据库数据） | 5-15GB |
| 模型权重（BGE-M3 + Reranker + 微调基座） | 8-15GB |
| Torch CUDA 版（P04 需要） | 3-4GB |
| 数据集 / 样例视频 / 素材 | 3-8GB |
| **合计** | **约 45-85GB** |

**D 盘剩 64G，属于"刚好卡在边缘"**。一旦哪个环节膨胀（如 Docker 镜像残留、多次重装依赖），立刻爆盘。

### 处置方案（重要）

**策略：代码留 D 盘，一切"可再生的重物"全部迁到 E 盘。**

| 迁移对象 | 做法 |
|---|---|
| Docker 镜像与卷 | Docker Desktop → Settings → Resources → **Disk image location 改到 E 盘**（搬迁已有镜像会自动完成） |
| uv / pip 包缓存 | 设环境变量 `UV_CACHE_DIR=E:\cache\uv`、`PIP_CACHE_DIR=E:\cache\pip` |
| HuggingFace 模型权重 | 设 `HF_HOME=E:\cache\hf`（BGE、LoRA 基座都走这里） |
| npm 缓存 | `npm config set cache E:\cache\npm --global` |
| Torch 模型缓存 | `TORCH_HOME=E:\cache\torch` |
| 大文件产物（切片视频、素材图） | 项目内 `data/` 目录用符号链接指向 E 盘，或直接在 E 盘建 media 目录 |

> **执行前会再跟你确认一次**（涉及全局环境变量与 Docker 配置变更）。
> 如果你正在让"马维斯"清理磁盘，**清理完成后再执行迁移**，避免两边同时动盘。

| 项 | 内容 |

| 中间件 | **Milvus 2.5.5 + etcd + MinIO + MongoDB**（docker-compose 已备好，4 个容器） |
| 现有能力 | **BGE-M3 稠密+稀疏双通道** / HyDE 假设文档扩展 / MCP 联网 / RRF 多路融合 / **BGE-Reranker 精排 + 断崖检测动态截断** / SSE 流式 / MongoDB 会话历史 / **答案溯源（chunk_id + 相关度）** / 反馈闭环 / SHA256 增量入库 / owner 权限隔离 |
| 启动难度 | 🔴 **高** |
| 磁盘预估 | torch CUDA ~3GB + BGE-M3 ~2.3GB + Reranker ~1.1GB + Docker 镜像 ~5GB ≈ **11GB+**，下载等待时间长 |
| 改造重点 | 见下方「关键优化建议」 |

#### 🔑 关键结论（已复核，比初判更乐观）

**本地已经有完整模型文件**（详见 `10-本地模型资产清单.md`）：

| 模型 | 路径 | 体积 |
|---|---|---|
| `BAAI/bge-m3`（稠密 + 稀疏） | `D:\ai_models\modelscope_cache\models\models\BAAI--bge-m3` | ~4.3G |
| `BAAI/bge-reranker-large` | `D:\ai_models\models\BAAI--bge-reranker-large\snapshots\master` | ~6.3G |

**因此方案定为：向量化与重排全部走本地，不依赖云端。**

| 项 | 原估 | 实际 |
|---|---|---|
| 模型下载 | ~3.4GB | **0**（本地已有） |
| torch CUDA | 3-4GB | 3-4GB（绕不开，BGE 系列的运行时） |
| **合计新增** | ~7GB | **~3-4GB** |

> **为什么不走云端**：`Token Plan`（`sk-sp-`）端点上**根本没有 embedding / rerank 模型**；`Coding Plan`（`sk-ws-`）虽有，但官方限定 "Coding tools only"，拿来跑应用踩条款灰区。

**仍建议保留「可切换后端」设计**（`EMBED_BACKEND=local|cloud`，**默认 local**）—— 面试被问"能不能私有化部署、数据不出内网"时，答案是"**本来就是本地的**"，比"我可以切本地"更有说服力。

同时 Docker 里可以**先不用 MinIO**（文件存本地磁盘），只起 Milvus + etcd，省内存。MongoDB 用于会话历史，可后置。
