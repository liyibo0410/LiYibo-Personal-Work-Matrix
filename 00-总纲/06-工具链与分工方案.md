# 工具链与分工方案

> 回答两个问题：**① 哪个环节用什么工具 ② 怎么把这套东西交给 Qoder 做**

---

## 一、总体分工：三层三条线

```
┌──────────────────────────────────────────────────────────────┐
│  第 1 层 · 规划与验证（WorkBuddy / 我）                        │
│  · 架构设计、总纲提示词、技术选型决策                          │
│  · 项目体检、环境迁移、磁盘与依赖治理                          │
│  · 跑通验证、截图录屏存证、写面试讲稿                          │
├──────────────────────────────────────────────────────────────┤
│  第 2 层 · 编码执行（Qoder IDE）  ← 主力干活的地方              │
│  · Agent 模式：既有项目批量改造                                │
│  · Quest 模式：新项目从零搭建（Spec 驱动）                     │
│  · Repo Wiki：理解既有代码                                     │
│  · Browser Agent：前端效果自验                                 │
├──────────────────────────────────────────────────────────────┤
│  第 3 层 · 交付上线（最后阶段）                                │
│  · Docker 打包 → 服务器部署（nginx / 宝塔）                    │
└──────────────────────────────────────────────────────────────┘
```

## 三、Qoder 专项方案（重点）

### 3.1 它是怎么工作的

| 能力 | 机制 | 对你怎么用 |
|---|---|---|
| **规则** | `.qoder/rules/*.md`，项目级，可提交 git；**兼容 `AGENTS.md`**；所有规则**合计上限 100,000 字符** | 把总纲拆成主题规则文件放这 |
| **记忆** | `~/.qoder/AGENTS.md`（用户级）/ `/AGENTS.md`（项目级）/ `/AGENTS.local.md`（本机私有） | 项目级放规范，本机私有放端口、本地路径 |
| **Repo Wiki** | 一键扫描仓库生成结构化文档到 `.qoder/repowiki/` | 接手旧项目第一步就跑它 |
| **Quest** | 需求 → 自动澄清 → 生成 Spec（带 Mermaid 图）→ 你审核 → 并行子任务 → 编码+自测 → 交付清单 | 新项目主力模式 |
| **Agent** | 自主拆解、多文件修改、跑终端 | 旧项目改造主力模式 |
| **Subagent** | `.qoder/agents/*.md` 自定义（frontmatter 定义 tools/model/skills/mcpServers） | 可做"架构评审员""测试补齐员" |
| **模型** | 可接**阿里云百炼 Coding Plan**（填 sk- key，选 Qwen-Coder 系列） | **你已有百炼账号，直接接** |

### 3.2 工作区怎么组织（关键）

**Qoder 的工作区 = 一个文件夹 = 一个项目边界**。所以：

```
方式一（推荐）· 一个工程一个工作区
  D:\software\PycharmProjects\面试项目\projects\p02-ecommerce-ops-assistant   ← 开一个 Qoder 窗口
  D:\software\PycharmProjects\面试项目\projects\p06-data-platform              ← 另开一个
  优点：规则互不干扰、Credits 消耗可控、Quest 任务边界清晰

方式二 · 整个 面试项目 当一个工作区
  优点：能跨项目改（做整合阶段时需要）
  缺点：Repo Wiki 索引大、规则要涵盖全部、上下文易被稀释
```

**建议**：日常用方式一，**做 Phase 12 一体化整合时切到方式二**。

### 3.3 把总纲拆成 Qoder 能吃的形式

总纲提示词约 2 万字符，**一个文件塞得下（上限 10 万）**，但全塞进去不划算——每个项目工作区只需要它自己那部分。

**已为你生成的文件结构**：

```
面试项目\
├── AGENTS.md                      ← 项目级通用规则（Qoder 自动识别）
├── .qoder\
│   └── rules\
│       ├── 01-架构与目录约定.md
│       ├── 02-技术规范.md
│       ├── 03-红线与安全.md
│       └── 04-验收门禁.md
└── projects\
    └── pXX-xxxx\
        └── AGENTS.md              ← 各项目自己的任务卡（开工前生成）
```

**用法**：
1. 打开某个项目工作区 → Qoder 自动加载该目录及其父目录的 `AGENTS.md` 与 `.qoder/rules/**`
2. 开工时把该项目 `AGENTS.md` 里的任务卡内容**直接粘进 Quest / Agent 对话**
3. 每完成一个模块，让 Qoder 更新 `AGENTS.md` 的进度勾选

### 3.4 模型接入（你有现成优势）

阿里云百炼 → 开通 **Coding Plan** 订阅 → 生成专属 API Key → Qoder 设置里模型服务商选"阿里云百炼" → 粘贴 Key → 选 Qwen-Coder 系列。

> ⚠️ 注意：**日常开发用 Auto 或 Efficient 就够了**，别默认开 Ultimate（Credits 消耗约 1.6 倍）。Quest 大任务才切性能档。

### 3.5 官方踩坑提示（直接抄）

| 坑 | 官方给的解法 |
|---|---|
| Quest 大任务中途 Credits 耗尽 | **拆成 10-20 个文件以内的子任务**分批提交，不要一次让它改 50 个文件 |
| Agent 误删配置文件 | **在规则里写"禁止删除文件清单"**，涉及配置变更强制人工确认（我在 `03-红线与安全.md` 里已经写了） |
| Repo Wiki 与代码不同步 | 大改动后手动刷新 Wiki |
| 多人/多项目规则冲突 | 项目级规则优先级最高，冲突时删本地配置 |

### 3.6 我能配合做什么

Qoder 是 IDE 里干活的，我做它做不了或做不好的：

- **环境与磁盘治理**：Docker 存储迁移、缓存目录重定向、依赖清理（Qoder 不擅长这类系统级操作，风险也高）
- **真跑验证与存证**：Qoder 说"改完了"，我实际跑一遍、截图、写进 `_evidence/`
- **跨工具协调**：帮你生成各项目的 `AGENTS.md` 任务卡、随进度更新
- **讲稿与文档**：面试话术、架构图、项目问答
- **决策把关**：技术选型有分歧时给判断

> **一句话分工**：Qoder 写代码，我管环境、验证和表达。

## 四、推荐执行流（给 Qoder 的具体操作顺序）

以 P02 电商运营助手为例：

```
① WorkBuddy（已做）  → 体检报告确认可跑、环境就绪
② Qoder 打开 p02 工作区
③ Qoder · Repo Wiki  → 生成项目理解（几分钟）
④ 粘贴 p02/AGENTS.md 任务卡进 Quest，选 Spec 模式
⑤ 审核生成的 Spec（重点看：要改哪些文件、验收标准是什么）
⑥ 执行 → 用 Browser Agent 自验前端
⑦ 回来找我 → 我实际跑一遍、截图、写 _evidence
⑧ 让 Qoder 更新 AGENTS.md 进度
```

**为什么第 ⑦ 步不能省**：Qoder 的"完成"是它自己的判断，我的"跑通"是实际执行结果。面试时你能拿出的证据，必须是后者。

## 五、给你的三条建议

1. **先让我把环境治理完**（磁盘迁移 + 缓存重定向），再大规模交给 Qoder 生成代码。否则 64G 空间会在依赖安装阶段爆掉。
2. **Qoder 只接百炼，别再开第二家**。你已有的端点上 LLM / Embedding / Rerank / 文生图 / TTS 全覆盖，工具链越简单越稳。
3. **里程碑 A 期间，Qoder 只做 P02 和 P05**。P04 涉及 Docker 中间件与向量化链路，环境依赖多，等磁盘腾出来再做更稳。
