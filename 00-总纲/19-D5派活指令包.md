## 任务卡 A —— Reranker 双后端（本地优先）★ 立即开工，不依赖 Docker

```
【背景 · 必读】
本项目的检索链路是：稠密向量 + 稀疏 BM25 双路召回 → HyDE → RRF 融合 → 【重排】→ 生成答案。
其中 Embedding 早就是本地 BGE-M3（utils/embedding_utils.py），
但【重排】这一步还在调云端 DashScope API：

    utils/reranker_http_utils.py:9
        def rerank_documents(query: str, documents: list[str]) -> list[float]:
            dashscope.api_key = reranker_config.text_rerank_api_key
            response = dashscope.TextReRank.call(...)      ← 云端，要钱 + 要出网

而 config/app 层面【本地重排模型的配置早就写好了，却从未被任何代码使用】：
    .env:  BGE_RERANKER_LARGE=D:\ai_models\modelscope_cache\models\BAAI\bge-reranker-large
           BGE_RERANKER_DEVICE=cuda:0
           BGE_RERANKER_FP16=1
    （全库 grep BGE_RERANKER 在 .py 中零命中 —— 配置备了、模型下了、线没接）

【为什么值得做 —— 这是面试加分项，请理解意图再动手】
合同 / 技术手册这类敏感文档，重排要把正文送到云端 API。
把重排也拉回本地，"全链路私有化部署"的叙事才闭环：
    embedding 本地 ✅（已有） + 重排 本地 ✅（本次补） = 敏感文档不出网
同时省掉一次 API 调用（降本 + 降延迟）。

【要做的】

1) 扩展配置 config/reranker_config.py：
   - 新增 backend（读环境变量 RERANK_BACKEND，取值 local|cloud，默认 local）
   - 新增本地模型相关字段：bge_reranker_path / device / fp16
     （直接复用 .env 里已有的 BGE_RERANKER_LARGE / BGE_RERANKER_DEVICE / BGE_RERANKER_FP16）
   - 保留原有 text_rerank_* 字段（cloud 通道继续用），不要删

2) 改造 utils/reranker_http_utils.py 的 rerank_documents()：
   - 【签名保持不变】：(query: str, documents: list[str]) -> list[float]
     返回与 documents 等长的分数列表（分数越高越相关）
   - backend=local：加载本地 bge-reranker-large 做交叉编码打分
   - backend=cloud：沿用现有 dashscope.TextReRank.call
   - 【三级降级，绝不阻断】：
       local 失败（未装依赖 / 模型路径不存在 / CUDA 不可用 / 推理报错）
         → 自动降级 cloud
       cloud 也失败（无 Key / 网络错误 / 配额）
         → 降级「不重排」，返回等长且保序的分数（例如按原始顺序给递减分），
           并在日志/返回值里标明降级原因
   - 本地模型【单例缓存】：不要每次调用都重新加载模型（首次加载 2GB，很慢）

3) 依赖处理：
   - 先查 pyproject.toml 里是否已有 FlagEmbedding 或 transformers
   - 本地重排建议用 FlagEmbedding 的 FlagReranker（与 BGE 系列同源，最省事）；
     若不想新增重依赖，用 transformers + AutoModelForSequenceClassification 自行实现交叉编码也可以
   - 新增依赖必须写进 pyproject.toml，并说明安装方式
   - 【关键】依赖缺失时不能 import 崩溃 —— 用 try/except 包住 import，
     让 backend=local 在缺依赖时自动降级 cloud

4) 设备选择：
   - 读 BGE_RERANKER_DEVICE（当前 cuda:0）；CUDA 不可用时自动退 cpu
   - 顺带把 embedding 的 BGE_DEVICE 也加一个自动检测（当前 .env 写死 cpu，
     而本机有 RTX 4060 Laptop 8GB）—— 有 CUDA 就用 cuda，没有才 cpu

【验收（必须逐条给证据，不要只说"通过了"）】
1. 【正常路径 · 真跑一遍】backend=local 且本地模型可用时，
   给 3-5 条明显相关/不相关的候选文档，本地重排给出的分数排序【必须与语义相关度一致】
   （贴出 query + 候选 + 分数，让人能判断排序对不对）
2. 同一组输入，local 与 cloud 两种后端的 Top-1 【应一致或高度接近】（允许分数尺度不同）
3. 【降级路径】：手动把模型路径改成一个不存在的路径 → 应自动降级 cloud 或"不重排"，
   且**不抛异常**、检索流程继续
4. 【依赖缺失】：模拟 FlagEmbedding 未安装 → 不 import 崩溃，自动降级
5. 单元测试不依赖 Milvus / MongoDB / MinIO / Docker —— 纯函数级，能独立跑
6. 重复调用 100 次，验证模型只加载一次（单例缓存生效，贴耗时对比）

【禁止】
- 不要改 rerank_documents() 的签名与返回类型
- 不要因为接本地重排就删掉 cloud 通道（双后端是卖点）
- 不要在没有降级保护的情况下让主流程依赖本地模型
```
